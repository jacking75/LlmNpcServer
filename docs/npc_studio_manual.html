NPC Studio 사용 설명서

이 마을의 NPC 를 읽고 · 예측하고 · 만드는 도구다. 1장부터 7장까지는 JSON 을 한 번도 보지 않고 따라갈 수 있다. 각 장은 화면 하나와 목표 하나를 다룬다.

읽기 3분하루 예측 재생연습장 · 되돌리기저장 전 전체 검증

1. 처음이라면

1.1 실행한다

저장소 루트의 PowerShell 에서 실행하고 http://127.0.0.1:25056 을 연다.

dotnet run -c Release --project tools/Npc.Studio

반복 실행할 때는 빌드와 실행을 나눈다. 옵션은 DLL 뒤에 그대로 붙는다.

dotnet build tools/Npc.Studio/Npc.Studio.csproj -c Release
dotnet .\tools\Npc.Studio\bin\Release\net10.0\Npc.Studio.dll --read-only --port 25057
서버 본체와 별도 프로세스다. 게임이 도는 Npc.Host 에 편집 UI 를 끼워 넣지 않는다. 실행 중인 서버는 9장 라이브 관찰에서 HTTP 로만 들여다본다.

1.2 알아야 할 말은 넷뿐이다

말뜻예
직업 (아키타입)NPC 의 종류다. 성격·할 수 있는 행동·하루 일과가 여기 모여 있다.대장장이, 위병, 수련사제
NPC (개체)직업으로 생성된 한 명이다. 한 명만 다르게 할 수 있다.위병 #2326
장소 (POI)사는 곳·일하는 곳이다. 정원과 여는 시간이 있다.대장간, 선술집, 성문
지역 (존)장소들의 묶음이다. 이웃으로 이어진다.장인 구역, 시장

이 넷의 관계는 한 줄이다 — 직업이 NPC 를 만들고, NPC 는 지역 안의 장소에서 산다.

1.3 화면 지도

왼쪽 · 메뉴

초보자 여정 순서다. 시작 → 직업 → NPC → 지도 → 장소 → 돌발 반응 → 행동 → 라이브 → 검증 → 고급.

가운데 · 작업

고른 것의 개요·예측·편집이 나온다. 주소창에 URL 이 남으므로 링크로 공유할 수 있다.

오른쪽 · 검증 결과

언제나 여기 있다. 0 이면 이 마스터데이터로 서버가 뜬다.

위쪽 막대에는 전역 검색(직업·NPC·장소를 한국어나 ID 로), 전체 검증, 새로고침(외부 편집기의 변경까지 다시 읽는다), 도움말(지금 화면에서 할 수 있는 일)이 있다.

따라하기가 스스로 체크된다. 시작 화면의 따라하기 열기 를 누르면 첫 10분 체크리스트가 뜬다. 화면에 들어가고 버튼을 누르면 줄이 ✓ 로 바뀐다. 진행은 이 브라우저 탭에만 남는다.

1.4 망가뜨려도 되나

된다. 두 가지 안전장치가 있다.

  • 연습장 — 시작 화면의 연습장 만들기. 원본을 통째로 복사하고 거기서 편집한다. 연습장에서 저장해도 원본은 바이트 하나 변하지 않는다.
  • 저장 전 검증 — 저장 버튼은 원본을 바로 덮어쓰지 않는다. 검증이 실패하면 원본은 그대로다. 자세한 것은 8장.

2. 따라하기 — 대장장이를 읽는다

목표. 대장장이가 어디서 살고, 무엇을 하고, 위험하면 어떻게 하는지 를 3분 안에 말할 수 있다. 시작 화면에서 클릭 4회 안이다.
  1. 왼쪽 직업 을 누른다. 40개 직업이 직군별로 나온다.
  2. 대장장이 를 고른다. 개요 탭이 기본이다.
  3. 위에서부터 읽는다 — 한 문장 요약 → 사는 곳·일터 → 성향 막대 → 할 수 있는 행동 → 위험할 때 → 인구.
  4. 모르는 칸이 있으면 이름 옆 ⓘ 를 누른다. 그 필드가 무엇이고 어디에 쓰이는지 가 나온다.

2.1 개요가 답하는 것

칸읽는 법
사는 곳 · 일터유형이다. "집" · "대장간" 처럼 나온다. 실제로 어느 건물인지는 NPC 마다 다르고, 그것은 4장에서 본다.
성향근면 · 사교 · 용기 · 탐욕 넷이 0~100 막대다. 용기는 위험할 때의 반응을 가른다 — 3장에서 직접 내려 본다.
할 수 있는 행동이 직업에게 허용된 행동이다. 한국어 표기가 앞이고 영어 id 는 부제다.
위험할 때돌발 반응(인터럽트) 규칙 중 이 직업에 걸리는 것만 추린 것이다. 조건과 결과가 같이 나온다.
인구전체 NPC 중 이 직업이 몇 명인가. 옆에 지역별 분포가 같이 나온다.
하루 일과LLM 이 없어도 도는 기본 계획이다. 스텝마다 ✓ / ✗ 판정이 붙는다 — ✗ 는 그 스텝의 전제조건이 안 맞는다는 뜻이다.
✗ 가 보이면 그것은 발견이다. 정의가 검증은 통과하지만 실제로는 매번 실패하는 스텝일 수 있다. 검증·진단 화면의 건강 진단이 같은 것을 목록으로 모아 준다.

2.2 전문가 카드

전문가 카드 탭은 검수용이다. 근거 파일과 검증 코드(archetypes.json · V5)가 같이 나오고, 값은 영어 id 그대로다. npc card archetype blacksmith 와 같은 내용이다 — 리뷰할 때 쓰고, 처음 읽을 때는 개요를 본다.

3. 따라하기 — 하루를 재생한다

목표. 정의를 읽는 것에서 "그래서 이 NPC 가 어떻게 움직이지?" 로 넘어간다. 값을 바꾸면 무엇이 달라지는지 눈으로 본다.

3.1 재생한다

  1. 대장장이 → 하루 미리보기 탭.
  2. ▶ 하루 재생 을 누른다. 지도 위의 인형이 집 → 대장간(일하기) → 선술집 → 집(잠) 으로 움직인다.
  3. 위의 24시간 띠에서 아무 구간이나 누르면 그 시각으로 건너뛴다. 배속 으로 속도를 바꾼다.
  4. 아래 카드가 지금 무엇을 왜 하는지 를 문장으로 말한다.
예측은 결정론이다. 같은 정의면 언제 눌러도 같은 타임라인이다. 소요 시간은 시뮬레이터(Npc.Sim)가 쓰는 것과 같은 계산이다 — 지터(±) 만 빼고 같다. 두 곳에 같은 식을 두 번 적지 않았다는 뜻이고, 드리프트 테스트가 그것을 지킨다.

3.2 상황을 준다

타임라인 아래 상황 버튼이 일곱 개 있다.

위협 등장전투 시작부상적대 플레이어플레이어가 말을 건다피해 입음혼자 위협
  1. 위협 등장 을 누른다. 대장장이는 물러나기(retreat_on_threat) 로 성문을 향한다.
  2. 아래 왜 패널이 규칙 판정을 한 줄씩 보여 준다 — 어떤 조건이 맞았고 어떤 것이 안 맞았는지.
  3. 돌아가기 로 평소 하루로 되돌린다.

3.3 값을 바꿔 본다 — "기대 경로" 의 뜻

  1. 편집 탭으로 간다. 용기 막대를 55 → 30 으로 내린다.
  2. 저장하지 않아도 오른쪽 예측이 즉시 바뀐다. 같은 위협 등장 이 이제 도망(flee_on_threat) 이다.
  3. "왜" 패널에 flee_on_threat: 용기 30 < 40 ✓ 가 뜬다. 규칙의 문턱값이 40 이었고, 30 이 그 아래로 내려간 것이다.
  4. 아래 변경 요약이 같은 말을 문장으로 적는다 — "용기 55 → 30. 위협 시 물러나기 대신 도망친다."
여기까지는 아무것도 저장되지 않았다. 예측은 화면의 초안으로 계산한다. 저장은 검증하고 저장 을 눌러야 일어나고, 그때 전체 검증을 다시 돈다.

기대 경로란 "이 정의면 NPC 가 이렇게 움직일 것이다" 라는 예측이지 실행 기록이 아니다. 실제 서버에서 명령이 유실되거나 장소가 만원이면 달라진다 — 실제를 보려면 라이브 관찰을 쓴다.

4. NPC 한 명을 고친다

목표. 위병 #2326 의 순찰로를 지도에서 3곳 찍어 바꾸고 저장한다. 좌표를 손으로 적지 않는다.
  1. 왼쪽 NPC → 위쪽 검색에 #2326. # 을 붙이면 그 번호만 나온다 — 붙이지 않으면 2326 을 품은 모든 값이 걸린다. 직업·지역으로 좁히거나 개별 설정이 있는 NPC만 필터를 쓸 수도 있다.
  2. 행을 누르면 누구인가 · 어디 사는가 · 무엇을 하는가 가 한 화면에 나온다. 통근 거리와 하루 예측도 이 NPC 기준으로 다시 계산된 값이다.
  3. 어디에 사는가 지도에서 장소를 누르면 순찰 지점으로 들어가고 선이 바로 바뀐다. 집과 일터에는 별도 표시가 붙고, 이미 고른 곳은 흐려진다. 4곳을 넘기거나 같은 곳을 또 누르면 그 이유를 말해 준다.
  4. 순서를 ↑ ↓ 로 바꾸고 × 로 뺀다. 최대 4곳이고 같은 지역이어야 한다.
  5. 아래 개별 설정 에서 공격 반경(0~200m) · 세력 · 대화 프로필 · 일정 오프셋(-120~120분)을 채운다. 각 칸의 ⓘ 가 뜻을 말한다. 세력은 설명으로 고르고, 대화 프로필은 이미 쓰인 값이 후보로 나온다.
  6. 검증하고 저장. 개별 설정 삭제 는 무엇이 지워지는지 세어 확인을 받은 뒤 지운다 — 그 NPC 는 직업의 기본값으로 돌아간다.
  7. 순찰로에 POI ID 를 직접 입력할 수도 있다. 순찰 경로 칸 아래의 접이식 POI ID를 직접 입력한다 를 편다 — 쉼표나 줄바꿈으로 구분하고, 목록에 없는 ID 는 저장 검증에서 거절된다.
생성물은 고치지 않는다. NPC 5,000명 명단(npc_instances.json)은 생성기가 만든다. 한 명만 다르게 하는 값은 npc_overrides.json 에 들어가고, Studio 가 그 파일의 해당 ID 항목만 추가·교체·삭제한다.

지도 좌표는 지역 안에서만 실제다. 지역끼리 합칠 절대 좌표는 마스터데이터에 없다 — 마을 전체 배치는 마을 지도 화면이 지역 단위로 보여 준다.

5. 장소를 더한다

목표. 양봉장 두 곳을 만들고 거리표를 다시 굽는다.
  1. 왼쪽 지역·장소 → 지역을 하나 고른다. 그 지역의 장소가 지도와 목록으로 나온다.
  2. + 새 장소 를 누른다.
  3. 세부 종류를 정하면 장소 ID 가 제안된다(쓰이지 않은 최소 번호). 이미 있는 ID 나 형식이 틀린 ID 는 입력하는 순간 막힌다.
  4. 처음 보는 세부 종류면 그 자리에서 한국어 · 영어 이름을 묻는다. 그 이름은 poi.<세부 종류> 키로 같은 저장에 로케일 파일까지 들어간다 — 따로 넣으면 장소만 생기고 이름이 빠진 채 남는다. 비우면 세부 종류를 그대로 쓴다.
  5. 유형 · 정원 · 여는 시간을 채운다. 정원 칸 아래가 "이 유형을 쓰는 직업 인구를 감당하는가" 를 그 자리에서 말한다(V10).
  6. 좌표는 아래 지도를 클릭하면 찍힌다 — 점선 원이 새 장소 자리를 미리 보여 준다. 숫자로 직접 넣어도 된다.
  7. 일할 수 있는 직업은 체크 목록, 얻을 수 있는 것은 아이템 선택이다. code 는 자동으로 다음 번호가 잡힌다 — 번호를 손으로 적거나 재배치하지 않는다.
  8. 검증하고 만들기. 하나 더 만들어 둘로 채운다.
  9. 저장 직후 파급 패널이 뜬다: 거리표(poi_distances.bin)가 낡았다. 다시 만들기 를 누른다.
기존 장소의 편집·삭제는 아직 없다. 정원·시간·허가를 고치려면 고급 · JSON 의 pois.json 에서 한다. 삭제는 번호 체계를 흔들어 미리 구운 계획과 명단이 가리키는 자리를 비우므로 npc CLI 로 파급을 보고 한다 — Studio 는 번호 삭제를 저장 단계에서 거절한다.
왜 저장이 먼저이고 재생성이 나중인가. 장소를 더하면 거리표는 그 순간부터 낡은 것이 맞다 — 243개 기준으로 구운 표에 244번째가 없다. 로더는 이것을 옳게 거절하지만, 거리표를 다시 구우려면 새 장소가 먼저 파일에 있어야 한다. 그래서 장소 추가만은 "거리표가 낡았다" 를 이유로 저장을 막지 않고, 대신 파급 패널이 바로 다음 할 일을 시킨다. 다른 모든 저장은 이 예외가 없다.

같은 이유로 화면도 막히지 않는다 — 거리표가 낡으면 Studio 는 거리 없이 읽고 위쪽에 배너를 띄운다. 그 상태에서는 소요 시간 예측을 믿을 수 없다(거리가 전부 0 이다). 다시 만들면 원래대로 돌아온다.

재생성이 끝나면 derived.lock.json 의 신선도 잠금도 같이 갱신된다. 터미널에서 확인하려면 npc regen --check 다 — 낡은 것이 없으면 0 을 낸다.

6. 새 직업을 만든다

목표. "양봉가" 를 만들어 --npcs 5000 기동에 실제로 뜨게 한다.

왼쪽 직업 → 새 직업 만들기. 5단계 마법사다.

1. 이름·직군→2. 닮은 직업·인구→3. 일터→4. 하루 일과→5. 확인
단계고르는 것화면이 답해 주는 것
1. 이름·직군ID(영문자로 시작하는 소문자·숫자·밑줄) · 한국어/영어 이름 · 직군이미 있는 ID 나 형식이 틀린 ID 는 입력하는 순간 막고 다음 을 잠근다. 직군은 저장되지 않는다 — ② 의 후보를 좁히는 데만 쓰고, 만든 직업은 목록에서 '기타' 로 묶인다(archetypes.json 에 직군 필드가 없다).
2. 닮은 직업·인구어디서 뗄까 · 몇 명인구 가중치의 합은 1 이다. 새 직업의 몫은 어디선가 와야 한다 — 재배분 방법 보기 가 세 가지 방법을 제안하고, 각각 어느 직업이 몇 명 줄어드는지 보여 준다. 인구를 바꾸면 안도 다시 계산된다. 쓸 수 있는 안이 하나도 없으면 다음 이 막히고 그 이유가 나온다.
3. 일터일터 유형정원이 인구를 수용하는가. 모자라면 다음 을 막는다 — 장소를 먼저 만들어야 한다(5장). 5단계 끝에서 V10 으로 거절당하지 않게 여기서 잡는다. 장소를 만들러 나갔다 돌아와도 입력은 남아 있다.
4. 하루 일과스텝 목록닮은 직업의 일과가 편집기에 들어온다. 여기서 바로 고치고 오른쪽에서 하루를 재생한다 — 스텝마다 ✓ / ✗ 판정이 붙고, 상한이 예상 소요보다 짧으면 경고한다. 원본의 레시피·아이템을 쓰는 스텝은 노란 표시가 붙는다.
5. 확인—바뀌는 파일 목록(코드가 만든다 — 실제로 쓰는 파일과 같다) · 근무 허가가 붙는 장소 · 인구 재배분 표 · 만든 뒤 해야 할 일. 만들기가 거절되면 어느 단계로 돌아가야 하는지 링크가 나온다.

검증하고 만들기 를 누르면 여섯 파일이 한 트랜잭션으로 바뀐다. 5단계가 그 목록을 그대로 보여 준다.

archetypes.json
새 직업 + 인구 재배분→fallback_plans.json
하루 일과→context_buckets.json
버킷 수→pois.json
일터 작업 권한→localization/ko-KR.json
한국어 이름→localization/en-US.json
영어 이름
표시 이름을 같이 넣는다. 없으면 화면이 npc.beekeeper 를 그대로 내고 검증이 V14 로 잡는다. 영어 이름을 비우면 ID 를 그대로 쓴다.
일터 작업 권한을 같이 준다. 복제한 일과는 원본 직업의 일터를 가리키는데, 새 직업은 그 장소에서 일할 권한이 없다 — 그대로 저장하면 V3.UNREACHABLE_POI 로 거절된다. 마법사는 같은 트랜잭션에서 해당 장소들에 새 직업의 작업 권한을 넣는다.

6.1 만든 뒤에 해야 할 일

파급 패널이 순서대로 시킨다. 둘 다 다시 만들기 버튼이 있다.

  1. NPC 명단 재생성 — 인구 가중치가 바뀌었으므로 5,000명 배치를 다시 뽑는다.
  2. 거리표 — 장소를 같이 만들었다면 필요하다.
  3. 프리베이크(선택) — 미리 구운 계획을 새 직업 몫만큼 더 굽는다. 하지 않아도 하루 일과로 돈다 — 플랜 스토어는 미스여도 폴백을 주므로 서버는 뜬다.

마지막으로 설명(desc)을 반드시 사람 문장으로 고친다. 이 문장은 LLM 프롬프트에 그대로 실린다 — TODO: 가 남아 있으면 건강 진단이 잡는다.

dotnet run -c Release --project src/Npc.Host -- --loopback --npcs 5000 --time-scale 600 --days 1 --no-llm

7. 상황별 계획을 본다

목표. "이 직업은 오후에 · 경계 상태에서 · 폭풍이 칠 때 무엇을 하나" 를 본다.

NPC 는 하루 일과 하나로만 살지 않는다. 시간대 × 지역 상태 × 날씨 조합마다 미리 구운 계획이 따로 있다. 직업 하나당 6 × 4 × 3 = 72칸이다.

  1. 수련사제 → 상황별 탭. 72칸 격자가 나온다.
  2. 칸의 색이 상태다 — 핀(사람이 검수해 고정) · 생성됨 · 폴백으로 돈다(미리 구운 것이 없음) · 없음.
  3. 오후 · 경계 · 폭풍 칸을 누른다. 그 계획이 스텝 판정과 함께 나오고, 지도에서 재생된다 — 신전으로 뛰어가 기도하고 쉬었다가 귀가해 잔다.
  4. 미리 구운 것이 없는 칸은 "폴백으로 돈다" 로 표시된다. 결함이 아니다 — 실제로 도달하는 버킷은 전체의 9% 남짓이고, 나머지는 하루 일과로 돈다.
이 탭은 --planstore 경로가 있을 때만 나온다. 기본값은 ./planstore 다.

8. 저장은 어떻게 안전한가

8.1 저장 경로

저장 버튼은 원본을 바로 덮어쓰지 않는다.

임시 작업본→전체 검증 (V0~V14)→MasterDataLoader 로드→NpcInstanceTable 로드→백업→원자적 저장
결과동작
검증 통과바뀐 파일만 저장하고 화면을 다시 읽는다. 파급 패널이 다음 할 일을 말한다.
검증 실패원본을 유지한다. 문제는 고치던 화면 안에서 그 칸 아래에 나오고, 오른쪽 패널에도 제목·파일·그 자리로 가는 링크가 붙는다. 이 오류는 전역 검증 수에 섞이지 않는다 — 파일은 그대로이기 때문이다.
디스크가 바뀜읽은 뒤 밖에서(다른 탭 · VS Code · 생성기) 그 파일이 바뀌었으면 거절한다. 마지막 저장이 조용히 이기지 않는다 — 위쪽 새로고침 으로 다시 읽고 고친다.
번호 재배치code·bit 가 바뀌었거나 사라졌으면 거절한다. 미리 구운 계획 2,880건과 명단이 그 번호 위에 있다.
로더 실패형식은 맞지만 참조를 컴파일할 수 없다. 역시 저장하지 않는다.
저장은 한 묶음이다. 여러 파일을 쓰는 저장(마법사가 그렇다)은 전부 백업 → 전부 임시 파일 → 전부 교체 순서로 간다. 교체 도중 실패하면 이미 옮긴 것을 백업으로 되감는다 — 절반만 써진 상태는 사람이 손으로 풀 수 없다.
무변경 저장은 바이트 동일이다. 폼으로 열어 아무것도 바꾸지 않고 저장하면 파일이 한 바이트도 변하지 않는다. 바꾼 필드만 제자리에서 고치고 들여쓰기·키 순서를 원문에서 읽기 때문이다 — 한 줄을 고쳤는데 3,000줄이 바뀐 diff 는 아무도 리뷰할 수 없다.

8.2 연습장

  1. 시작 화면 → 연습장 만들기. 이름을 준다. 같은 이름이 이미 있으면 덮어쓰지 않고 묻는다 — 이어서 열기 와 새로 만들기 중 고른다.
  2. 위쪽 막대에 연습장 · 이름 배지가 뜬다. 이제 모든 편집은 사본에서 일어난다.
  3. 원본과 비교 로 무엇이 달라졌는지 본다. 표시 이름(localization/)도 비교에 든다.
  4. 마음에 들면 원본에 적용 — 이때도 검증을 다시 돈다. 연습장을 만든 뒤 원본이 바뀐 파일이 있으면 확인 모달이 그것을 먼저 말한다. 적용에 성공하면 원본으로 돌아간다.
  5. 버릴 때는 연습장 버리기. 무엇이 사라지는지 세어 확인을 받고, 지우는 대신 lab/.trash/ 로 30일 옮겨 둔다.
연습장은 탭이 아니라 도구 단위다. 한 탭에서 연습장을 열면 다른 탭도 그 폴더를 본다 — 다른 탭에는 배너로 알린다. 탭마다 다른 폴더를 보는 쪽이 오히려 위험하다: 원본인 줄 알고 연습장에 쓰게 된다.

8.3 백업에서 복원

낱말이 둘이다. 폼의 초안 취소 는 저장하지 않은 편집을 버리는 것이고, 백업에서 복원 은 이미 저장한 것을 되돌리는 것이다.

고급 · JSON 화면의 백업에서 복원 절에 저장 직전 상태가 시각순으로 쌓인다. 저장 한 번이 한 항목이다 — 마법사가 만진 여섯 파일을 같이 되돌린다. 하나만 되돌리면 어느 순서로도 V7 을 통과하지 못하기 때문이다. 복원도 다시 검증해서 저장한다.

가장 흔한 되돌리기는 방금 저장이다 — 저장 결과 카드의 방금 저장 되돌리기 가 그 묶음 하나를 되돌린다.

항목값
두는 곳%LOCALAPPDATA%\NpcStudio\backup\ 아래, 편집 대상 폴더마다 따로. --backup-root 로 바꿀 수 있다.
보존30일. 다만 파일별 최근 5개는 날짜와 무관하게 남는다 — 한 달 쉬었다 돌아온 사람에게 되돌릴 것이 하나도 없으면 안 된다.
범위Studio 가 쓰기 직전의 원본. 외부 편집기의 변경은 여기 없다.
masterdata/ 안에 백업을 두지 않는다. 폴더 전체를 읽는 연습장 복사와 콘텐츠 해시에 백업이 입력으로 섞인다.

8.4 파급 패널

저장 뒤에 나오는 패널이다. 무엇이 낡았고 무엇을 다시 만들어야 하는가 를 말하고, 가능한 것은 버튼을 준다.

바꾼 것낡는 것다음
장소 추가·좌표 변경poi_distances.bin거리표 다시 만들기
인구 가중치·직업 추가npc_instances.jsonNPC 명단 재생성
액션·아키타입 설명프롬프트 프리픽스 해시프리베이크 재실행(선택). 안 하면 폴백으로 돈다
재생성 버튼은 저장소 안에서, 원본 디렉터리에서만 돈다. 생성기는 tools/gen_*.cs 스크립트라 저장소 밖 폴더나 연습장에서는 실행하지 않는다 — 그때는 버튼이 비활성이고 터미널 명령을 알려 준다.
명단을 다시 만들면 번호가 가리키는 NPC 가 바뀔 수 있다. 인구를 옮긴 직업 뒤의 번호가 밀리기 때문이다. 개별 설정은 번호로 묶여 있으므로, Studio 는 재생성 전후를 견주어 엉뚱해진 개별 설정을 결과 카드에 적는다. 같은 지역 다른 직업은 V13 도 잡지 못한다.

9. 고급 — JSON · 전문가 카드 · CLI 대응표

9.1 JSON 원문 편집

고급 · JSON 화면에서 원천 파일을 직접 편집한다. 폼으로 되는 일은 폼에서 한다 — 원문 편집은 폼이 없는 파일에만 쓴다. 생성물(npc_instances.json · poi_distances.bin · prompt/)은 목록에 나오지 않는다.

직업 화면의 고급 · JSON 탭도 같은 성격이다. 폼과 같은 초안을 보며, 저장하지 않은 변경이 있으면 화면을 떠날 때 확인한다 — 탭 전환 · 왼쪽 메뉴 · 새로고침 · 탭 닫기 넷 다 그렇다.

world_flags.json·actions.json 처럼 번호 체계를 가진 파일은 목록에서 그렇게 표시되고, 저장할 때 바뀐 줄 수를 보여 주는 확인이 한 번 더 붙는다.

9.1.1 어디서든 찾기

Ctrl+K(macOS 는 ⌘+K)가 위쪽 검색 칸으로 간다. ↑↓ 로 고르고 Enter 로 이동, Esc 로 닫는다. 직업·지역·장소·행동·돌발 반응을 찾고, 숫자는 NPC 번호로 본다.

9.2 라이브 관찰

라이브 관찰 은 실행 중인 NPC 서버를 같은 지도 위에 얹는다. 예측과 실제를 나란히 본다.

dotnet run -c Release --project tools/Npc.Studio -- --server http://127.0.0.1:25055 --token <대시보드 토큰>

HTTP 질의만 한다 — Studio 는 서버 프로세스를 참조하지도, 조작하지도 않는다. 주소가 없으면 이 화면은 "서버 주소가 없다" 로 남는다.

9.3 실행 옵션

옵션기본값의미
--masterdata./masterdata열 마스터데이터 폴더.
--planstore./planstore미리 구운 계획. 없으면 상황별 탭을 숨긴다.
--server없음실행 중인 NPC 서버 주소. 없으면 라이브 관찰을 쓰지 않는다.
--token없음대시보드 토큰. 비면 헤더를 붙이지 않는다.
--backup-root%LOCALAPPDATA%\NpcStudio\backup되돌리기 백업 위치.
--bind127.0.0.1수신 주소. 기본값은 로컬에서만 접근된다.
--port25056웹 포트.
--read-only꺼짐저장을 막고 조회·검증만 허용한다. 폼도 비활성이고 편집 화면 위에 배너가 뜬다.
--help—이 표를 찍고 끝낸다.
외부 공개용 서비스가 아니다. 인증이 없으므로 --bind 0.0.0.0 으로 사내 공용망이나 인터넷에 노출하지 않는다. 루프백이 아닌 주소에 편집 모드로 띄우면 콘솔과 위쪽 막대가 경고한다.
모르는 인자는 거절한다. --readonly(오타)로 띄우면 뜨지 않고 도움말이 나온다 — 예전에는 그것을 무시하고 편집 모드로 떴다. 요청한 --masterdata 경로가 없어 저장소의 masterdata/ 로 떨어진 경우도 콘솔과 배지가 알린다.

화면에서 하는 일은 대부분 터미널에서도 된다. 같은 코어를 부르므로 답이 갈리지 않는다.

10. 문제 해결

증상확인할 것
페이지가 열리지 않는다.터미널의 실제 URL 과 포트 충돌. --port 로 옮긴다.
검증 실패로 저장되지 않는다.오른쪽 오류의 제목과 링크를 따라간다. 대부분 그 자리로 바로 간다.
poi_distances.bin 이 POI 243개 기준인데 pois.json 은 244개다정상이다. 장소를 더한 직후의 상태다 — 파급 패널의 거리표 다시 만들기 를 누른다(5장).
V3.UNREACHABLE_POI 가 새 직업에서 난다.일터에 그 직업의 작업 권한이 없다. 마법사로 만들면 자동으로 들어간다 — 손으로 만들었다면 해당 장소의 작업 권한 목록에 직업을 더한다.
새 직업이 기동에 안 보인다.NPC 명단 재생성을 했는가. 인구가 0명으로 반올림되지 않았는가(건강 진단이 잡는다).
하루 미리보기의 인형이 안 움직인다.브라우저 탭이 뒤에 있으면 브라우저가 애니메이션을 멈춘다. 탭을 앞으로 가져오거나 24시간 띠를 눌러 시각을 직접 옮긴다.
재생성 버튼이 비활성이다.저장소 밖 폴더이거나 연습장이다. 원본 디렉터리에서 누르거나 터미널에서 npc regen.
상황별 탭이 없다.--planstore 경로에 pinned/·plans/ 가 있는지 확인한다.
라이브 관찰이 비어 있다.--server 를 줬는가. 서버가 대시보드 토큰을 요구하면 --token 도 필요하다.
수정한 파일 전체가 diff 로 보인다.Studio 는 원문 서식을 보존한다. 외부 편집기의 줄 끝 설정이 파일과 같은지 확인한다.
매뉴얼 링크가 404 다.저장소의 기본 masterdata/ 를 열었는지 확인한다. 외부 폴더에서는 docs/ 를 자동으로 찾지 못한다.
화면이 통째로 "읽을 수 없다" 로 바뀐다.사유가 넷 중 하나다. 화면이 어느 것인지 말하고 그에 맞는 탈출구를 준다 — 파생물 없음/낡음이면 다시 만들기(또는 터미널 명령), JSON 문법 오류·로더 거절이면 원문 편집이나 백업 복원이다. 어느 경우든 방금 저장 되돌리기 와 연습장 조작(적용·돌아가기·버리기)이 같은 화면에 있다.
위쪽에 거리표가 낡았다 배너가 떠 있다.읽고 고치는 것은 그대로 된다. 다만 소요 시간 예측을 믿을 수 없다 — 거리가 전부 0 이다. 파급 패널의 다시 만들기 를 누르면 사라진다.
재생성이 끝나지 않는다 / 출력이 없다.첫 실행은 빌드 때문에 수십 초 걸린다. 출력은 패널 아래에 흐르고 취소 로 멈출 수 있다(상한 10분). dotnet 을 찾지 못했다 면 PATH 문제다 — 알려 주는 명령을 터미널에서 직접 돌린다.
이 계획을 컴파일하지 못했다 (상황별 격자).마스터데이터가 바뀐 뒤의 낡은 플랜 파일이다. 격자에서 ! 로 표시된 칸은 파일은 있는데 읽지 못한 것이고, 빈 칸(없음)과 다르다. 프리베이크를 다시 돌린다.
라이브 관찰에서 서버가 거절했다(401).--token 값이 서버의 대시보드 토큰과 같은지 본다. --server 에 http:// 가 빠지면 아예 "주소가 잘못됐다" 로 나온다.
연습장 원본에 적용이 실패한다.둘 중 하나다 — (1) 연습장을 만든 뒤 원본이 바뀌었다(확인 모달이 그 파일을 적는다), (2) 원본 기준으로 검증이 떨어진다. 장소를 더한 경우는 거리표를 이유로 막지 않는다 — 적용한 뒤 다시 만든다.
백업에서 복원이 거절된다.복원한 상태도 검증을 돈다 — 그 사이에 다른 파일이 바뀌어 짝이 맞지 않는 것이다. 더 최근 백업부터 차례로 시도하거나, 짝이 되는 파일을 같이 되돌린다(항목 하나가 이미 묶음이다).
하루를 그릴 수 없다 가 나온다.그 직업의 하루 일과를 찾지 못했다(V7). 검증·진단 화면의 링크를 따라가면 그 직업의 하루 일과 탭으로 간다.
재배분 안이 전부 ✗ 다.그만큼 뗄 재원이 없다. 인구를 줄이거나 닮은 직업을 바꾼다 — 같은 계열 안은 그 계열의 총량이 모자라면 만들어지지 않는다.
저장 버튼이 눌리지 않는다.셋 중 하나다 — (1) 읽기 전용으로 떴다(위쪽 배지), (2) 바꾼 것이 없다, (3) 초안이 컴파일되지 않는다(그 이유가 폼 위에 나온다).
밖에서 파일이 바뀌었다 배너 / 저장이 거절된다.다른 탭 · VS Code · 생성기가 같은 파일을 고쳤다. 위쪽 새로고침 으로 다시 읽으면 편집 화면이 새 값을 보여 준다.
