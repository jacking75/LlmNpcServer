NPC Studio 사용 설명서

NPC 직업과 개별 NPC 정의를 브라우저에서 조회·생성·편집하는 도구다. 저장하기 전에 전체 마스터데이터 검증과 실제 로더 검사를 수행해 깨진 JSON이 원본에 들어가지 않게 한다.

Blazor ServerV1~V13 검증서식 보존로컬 전용 기본값

1. 실행한다

저장소 루트의 PowerShell에서 실행한다.

바로 빌드하고 실행한다

dotnet run -c Release --project tools/Npc.Studio
# 브라우저에서 http://127.0.0.1:5090 을 연다

먼저 빌드한 뒤 실행한다

반복 실행하거나 빌드와 실행 단계를 분리하려면 Release DLL을 만든 뒤 직접 실행한다.

dotnet build tools/Npc.Studio/Npc.Studio.csproj -c Release
dotnet .\tools\Npc.Studio\bin\Release\net10.0\Npc.Studio.dll
# 브라우저에서 http://127.0.0.1:5090 을 연다

직접 실행할 때도 DLL 뒤에 옵션을 그대로 붙일 수 있다.

dotnet .\tools\Npc.Studio\bin\Release\net10.0\Npc.Studio.dll --read-only --port 5091
기본 경계다. Studio는 NPC 서버 본체와 별도 프로세스다. 게임 실행 중인 Npc.Host에 편집 UI를 끼워 넣지 않는다.

2. 화면을 이해한다

왼쪽 · 탐색

아키타입, 개별 NPC, 원천 JSON 파일을 선택한다.

가운데 · 작업

항목 JSON, 설명 카드, NPC 카드 또는 전체 파일을 편집한다.

오른쪽 · 검증

V1~V13 오류의 코드, 파일, JSON Pointer, 수정 힌트를 보여 준다.

상단의 전체 검증은 디스크에 있는 현재 상태를 다시 읽는다. 새로고침은 외부 에디터에서 바뀐 내용까지 다시 불러온다.

3. NPC 정의를 조회한다

아키타입을 본다

  1. 왼쪽에서 아키타입을 선택한다.
  2. 검색창에 blacksmith처럼 ID를 입력한다.
  3. JSON 편집 탭에서 원본 항목을 확인한다.
  4. 설명 카드 탭에서 인구, 정원, 성향, 허용 액션, 인터럽트와 폴백을 사람 말로 확인한다.

개별 NPC를 본다

  1. 개별 NPC 탭을 누른다.
  2. 1~5,000 사이 ID를 넣고 NPC 카드 열기를 누른다.
  3. 집, 일터, 거리, 순찰로, 세력, 공격 반경과 일정 오프셋을 확인한다.
생성물은 읽기 전용이다. npc_instances.json을 직접 편집하지 않는다. 특정 NPC의 차이는 npc_overrides.json에 기록한다.

4. 새 NPC 직업을 만든다

  1. 아키타입 → 새 직업 만들기를 누른다.
  2. 새 ID를 영문 소문자와 밑줄로 입력한다. 예: beekeeper
  3. 행동과 일터가 비슷한 기존 직업을 복제 원본으로 선택한다.
  4. 인구 가중치를 입력한다. 이 값은 복제 원본의 현재 가중치보다 작아야 한다.
  5. 검증하고 생성을 누른다.

Studio는 다음 세 파일을 한 트랜잭션으로 바꾼다.

archetypes.json
새 직업 + 원본 인구 분할→fallback_plans.json
폴백 플랜 복제→context_buckets.json
버킷 수 갱신
생성 직후 할 일이다. 설명에는 TODO:가 들어간다. JSON 편집 탭에서 세계관에 맞는 문장, 허용 행동, 목표, 소지품, 근무 시간을 반드시 검토한다. 이후 dotnet run tools/gen_npcs.cs로 개체 명단을 재생성한다.

5. JSON을 편집한다

JSON 파일 탭에서는 다음 원천 파일을 편집할 수 있다. npc_instances.json, poi_distances.bin, prompt/처럼 다시 생성되는 파일은 목록에 나오지 않는다.

특정 NPC의 성격을 바꾸려면 개별 NPC → 오버라이드 편집을 누른다. 예시는 다음과 같다.

{
  "$schema": "../docs/schema/npc_overrides.schema.json",
  "version": 1,
  "overrides": [
    {
      "id": 1247,
      "patrol_route": ["gate_east_001", "guardhouse_001"],
      "aggro_radius_m": 35,
      "faction": "town_guard",
      "dialogue_profile": "stern_guard",
      "schedule_offset_min": -15
    }
  ]
}

순찰 지점은 해당 NPC와 같은 존에 있어야 하고 최대 4개다. 공격 반경은 0~200m, 일정 오프셋은 -120~120분이다.

6. 검증하고 저장한다

Studio의 저장 버튼은 바로 원본을 덮어쓰지 않는다.

임시 작업본 생성→V1~V13 전체 검증→MasterDataLoader 로드→NpcInstanceTable 로드→원자적 저장
결과동작
검증 통과변경 파일만 원본에 저장하고 화면을 다시 읽는다.
검증 실패원본을 유지하고 오른쪽에 코드·위치·수정 힌트를 표시한다.
로더 실패형식은 맞지만 참조를 컴파일할 수 없는 상태다. 역시 저장하지 않는다.

편집을 마친 뒤에는 Studio 검증에 더해 저장소 루트에서 다음을 실행한다.

dotnet run --project tools/Npc.Cli -- validate
dotnet run --project tools/Npc.Cli -- diff
dotnet run --project tools/Npc.Cli -- regen --check

7. 파일별 역할을 구분한다

파일용도주의
archetypes.json직업, 성향, 행동, 인구code를 재배치하지 않는다.
npc_overrides.json특정 NPC의 순찰·세력·대화 성격사람이 편집하는 개체 파일이다.
fallback_plans.jsonLLM 없이도 실행할 기본 행동모든 아키타입에 하나가 필요하다.
actions.jsonLLM과 런타임이 쓸 행동 어휘code 재배치 금지다.
pois.json집·일터·장소와 정원인구를 수용해야 한다.
npc_instances.json생성된 5,000 NPC 명단직접 편집 금지다.

전체 스키마는 마스터데이터 레퍼런스에서 확인한다.

8. 실행 옵션을 사용한다

dotnet run -c Release --project tools/Npc.Studio -- --masterdata ./masterdata --bind 127.0.0.1 --port 5090 --read-only
옵션기본값의미
--masterdata./masterdata열 마스터데이터 폴더다.
--bind127.0.0.1수신 주소다. 기본값은 로컬에서만 접근된다.
--port5090웹 포트다.
--read-only꺼짐저장 기능을 막고 조회·검증만 허용한다.
외부 공개용 서비스가 아니다. 인증을 제공하지 않으므로 --bind 0.0.0.0으로 인터넷이나 사내 공용망에 직접 노출하지 않는다.

9. 잘 안 될 때 확인한다

증상확인할 것
페이지가 열리지 않는다.터미널의 실제 URL과 포트 충돌을 확인한다.
검증 실패로 저장되지 않는다.오른쪽 오류의 파일·JSON Pointer·수정 힌트를 따른다.
새 직업이 게임에 안 보인다.dotnet run tools/gen_npcs.cs를 실행하고 충분한 --npcs 수로 기동한다.
매뉴얼 링크가 404다.저장소의 기본 masterdata/를 열었는지 확인한다. 외부 폴더에서는 docs/를 자동으로 찾지 못한다.
수정한 파일 전체가 diff로 보인다.Studio는 원문 서식을 보존한다. 외부 편집기의 줄 끝 설정이 LF인지 확인한다.
