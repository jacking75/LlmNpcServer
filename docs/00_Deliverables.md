# 00. 최종 결과물 명세 (Deliverables)

> 로드맵 12주를 완주했을 때 **손에 남는 것**이 무엇인지 정의한다.
> 상위 계획: [`../LLM_NPC_Server_Plan.md`](../LLM_NPC_Server_Plan.md)

---

## 0. 한 문장 요약

> **"5,000마리 NPC가 마스터데이터로 정의된 가상 마을에서, LLM이 생성한 행동 플랜에 따라 살아 움직이고, 그 결과를 게임서버용 명령 패킷으로 쏟아내는 헤드리스 서버. 그리고 그 패킷을 받아 월드를 갱신하고 되돌려주는 게임서버 대역(Npc.Sim)."**

실제 네트워크 통신은 이번 범위가 아니다. `IGameServerLink` 인터페이스와 패킷 정의까지만 만들고, 구현체는 인프로세스 루프백을 쓴다. 나중에 실제 게임서버에 붙일 때 **NPC 서버 코드는 한 줄도 바뀌지 않는** 것이 목표다.

## 2. 데모 시나리오 — "무엇을 보여줄 것인가"

R&D의 최종 발표는 아래 3개 시나리오를 화면에서 돌리는 것으로 한다.

### 시나리오 A — "살아있는 마을" (기본 검증)

```
게임 시간 7일 × 60배속 = 실시간 168분
NPC 5,000 / 존 12 / POI 250
```

관측 포인트:
- 대장장이가 아침에 광산 → 낮에 대장간 → 저녁에 선술집 → 밤에 귀가하는 사이클이 **플랜대로** 도는가
- 시간대가 바뀔 때 플랜 캐시 키가 전환되며 마을 전체 행동이 자연스럽게 바뀌는가
- 틱 시간이 5,000 NPC에서 예산 내인가 (§목표: 100ms 틱 중 실행 시간 ≤ 20ms)
- 대시보드에서 캐시 히트율이 98% 이상을 유지하는가

### 시나리오 B — "공성 이벤트" (재계획 검증)

```
t=0     평시. 마을 정상 동작
t=+30m  ZoneStateChanged(zone_town, RegionState.War) 주입
t=+31m  → 캐시 키가 *.war.* 로 전환 → 마을 전체 행동 변화
        → 경비병: 성문 집결 / 농부: 성 안으로 피난
        → 대장장이: 무기 제작으로 목표 전환
t=+90m  RegionState.Peace 복귀 → 복구 행동
```

관측 포인트:
- 이벤트 주입에서 행동 변화까지의 **지연** (목표: 인터럽트 경로 ≤ 1틱, 플랜 교체 ≤ 3초)
- 인터럽트(즉시 반응)와 재계획(비동기 후속)이 분리되어 동작하는가
- 캐시 미스가 발생한 버킷만 LLM을 태우는가 (전량 재생성이 아니라)

### 시나리오 C — "LLM 없이도 돌아간다" (가용성 검증)

```
t=+10m  외부 API 전면 차단 (T2 kill)
t=+20m  로컬 dotLLM 프로세스 강제 종료 (T1 kill)
→ 이후에도 5,000 NPC가 캐시 플랜 + 폴백 플랜만으로 정상 동작
```

이게 통과하지 못하면 상용 투입 논의 자체가 불가능하다.

## 3. "결과물이 무엇이 아닌지" — 범위 밖 명시

| 항목 | 이번 범위 | 비고 |
|---|---|---|
| 실제 네트워크 통신 (TCP/UDP/직렬화) | ❌ | `IGameServerLink` 인터페이스 + 패킷 DTO까지만. §[02_GameServer_Link](02_GameServer_Link.md) |
| 실제 게임 클라이언트 / 렌더링 | ❌ | 대시보드와 로그로만 관측 |
| NPC 대화 생성 (자연어 대사) | ❌ | `Speak(DialogueId)` 로 ID만 보낸다. 대사 생성은 별도 과제 |
| 전투 AI / 스킬 로테이션 | ❌ | `CombatAction` 명령만 발행. 전투 판정은 게임서버 소관 |
| 패스파인딩 | ❌ | `MoveTo(PoiId)` 만 보내고 경로는 게임서버가 푼다. Sim은 직선 이동 + 고정 소요시간으로 근사 |
| 영속화 (DB) | △ | 플랜 스토어와 리플레이 로그는 파일. NPC 상태 DB는 인메모리 + 스냅샷 |
| 멀티 월드 / 샤딩 | ❌ | 단일 월드 5,000 NPC |
| 인증/보안/운영 배포 | ❌ | 사내 R&D 로컬 실행 |

## 4. 최종 수용 기준 (Definition of Done)

12주 종료 시점에 아래가 전부 참이어야 완주로 본다.

> **판정: 16개 중 9개 통과 · 7개 미달** (2026-07-27, T5-20).
> 표기 — `[x]` 통과 · `[-]` 미달 또는 미착수. 근거는 [`measurements/P5_gate.md`](measurements/P5_gate.md).
> **미달 7개 중 4개가 같은 뿌리다** — P4(스케줄러·티어링)와 전량 프리베이크가 미착수라
> 런타임 LLM 경로의 실측이 하나도 없다.

**기능**

- [x] 마스터데이터만 바꿔서 아키타입·POI·액션을 추가할 수 있다 (코드 수정 없이)
      — 액션·플래그·아키타입이 전부 `masterdata/` 에서 온다. V1~V11 이 기동 시 강제한다
- [x] 시나리오 A/B/C가 전부 통과한다
      — `Phase5GateTests.Gate_ThreeScenariosFinish` · 5,000 NPC 에서 각각 T5-09·§2 확인
- [x] `IGameServerLink` 구현체를 `Loopback` → `Null` → `Recording` 으로 교체해도 NPC 서버 코드가 안 바뀐다
      — T5-11. 런타임 세 프로젝트가 `Npc.Gateway` 를 **참조조차 하지 않는다**
- [-] 프리베이크 CLI가 2,880개 플랜을 5분 이내에 생성한다
      — **미달.** 288버킷 파일럿 115초 → 전량 외삽 **19분**. 전량 회차 자체가 미실행(T2-19)
- [x] 생성된 플랜을 사람이 열어서 고치고, 캐시에 pin 하면 그게 유지된다
      — `PlanStore.Pin` + `planstore/pinned/` 계층 + `tools/pin_plan.ps1`. 로드 시 `plans/` 를 덮어쓴다

**성능 (NPC 5,000 기준)**

- [x] 틱 실행 시간 p99 ≤ 20ms (100ms 틱 예산의 20%)
      — **0.37ms.** 예산의 1.9 %
- [x] 인지 스캔 대상 ≤ 150마리/틱
      — 150 (상한에 붙음)
- [-] 플랜 캐시 히트율 ≥ 98%
      — **미측정.** 전량 프리베이크가 없어 버킷 0/2,880 이다. 기제는 동작한다(T5-09 가 히트율 변화로 확인)
- [x] 게임서버 명령 송출 ≥ 2,000 cmd/s 를 할당 없이 처리 (배치 + 풀링)
      — 틱당 2,086 명령 = **20,860 cmd/s** · 틱 루프 할당 **0 B**

**품질**

- [-] 플랜 검증 실패율 ≤ 3%
      — **미달.** 4단 검증 통과율 78.3 %(고른 표본) / 67.7 %(연속 288) → 실패율 22~32 %
- [x] 골든 시나리오 50건 통과
      — 단언 합격률 **93.6 %** (206/220, 3회 중 2회 기준)
- [x] 리플레이 결정론: 같은 로그 재생 시 100% 동일한 명령 시퀀스
      — 기록 2회 바이트 동일 + 재생 명령 열 동일 (T5-07)

**비용/운영**

- [-] 외부 API 프롬프트 캐시 적중률 ≥ 95%
      — **미달.** 30.7~42.6 %. 95 %는 **명시적 캐싱** 전제이고 이 엔진 계열은 암시적이라 도달 불가
- [-] 일일 토큰 하드 캡 초과 시 자동 강등이 동작한다
      — **부분.** 프리베이크 예산 캡은 동작한다(`BudgetGuard`, T3-14). 런타임의 T2→T1 강등도
      기제는 있다(`ReplanBudget`, T4-06 · 단위 테스트로 확인) — 다만 티어를 켜고 잰 회차가 없어 실측이 없다
- [x] T1/T2 전면 차단 상태에서 시나리오 A가 통과한다
      — 시나리오 C 3단계. 5,000 NPC 게임 13일 완주 (T5-09)

**보고**

- [-] 블라인드 A/B 평가 결과가 정량으로 나와 있다
      — **결론 보류.** 자료 40건·양식·정답 키·통계 처리기는 준비. 참가자 0명이라 판정 없음
- [-] 오써링 공수 절감률이 측정되어 있다 (수동 작성 대비)
      — **부분.** 축 B(커버리지 72배)는 확정. 축 A 는 수작성 실측이 없어 민감도 표(81~95 %)로만 낸다
