LLM NPC 서버

로컬·외부 LLM을 행동 플랜 컴파일러로 써서 MMORPG NPC 5,000마리의 하루 일과를 상황별로 자동 생성하고, 결정론 런타임이 그것을 10Hz로 실행하며 게임서버에 명령을 송출한다. 이 책은 그 코드를 읽고 고치고 돌리기 위해 알아야 할 것을 처음부터 끝까지 정리한 것이다.

코드 13 프로젝트 · 테스트 1 태스크 196 / 203 완료 NPC 5,000 · 틱 p99 0.80 ms 플랜 버킷 2,880 (도달 264) 문서 기준일 2026-08-01

한 문장 — LLM은 느리고 비싸게 플랜을 만들고, 런타임은 빠르고 재현 가능하게 실행한다. LLM이 전부 죽어도 NPC는 멈추지 않는다. 이 분리가 이 저장소의 전부다.

이 책이 답하는 것

저장소에는 이미 사양 문서가 20개 넘게 있다. 그것들은 무엇을 왜 만드는가를 정한 문서이고, 구현 순서를 지시하는 문서다. 반면 이 책은 이미 만들어진 코드를 앞에 두고 답한다 — 이 파일은 왜 여기 있고, 이 상수는 왜 이 값이며, 이 값을 바꾸면 무엇이 어떻게 달라지는가.

다루는 것

  • 구조가 왜 이렇게 되었는지 — 산술과 실측으로
  • 주요 타입·메서드의 역할과 호출 관계
  • 실행 옵션·설정·마스터데이터를 바꿨을 때의 동작 변화
  • 지표를 어떻게 읽고 무엇이 정상인지
  • 확장 절차 — 액션 추가, 아키타입 추가, 링크 교체

다루지 않는 것

  • API 레퍼런스의 전수 나열 — 그건 소스 주석이 이미 한다
  • C#·.NET 입문 — Span·Volatile 정도는 안다고 본다
  • 게임서버 구현 — 이 저장소는 NPC 서버만 만든다
  • 측정하지 않은 값의 추정 — 미측정은 미측정이라고 적는다
읽기 전에 알아둘 관점 하나 우리가 만드는 것은 NPC 서버다. 게임서버는 만들지 않는다. IGameServerLink의 "GameServer"는 상대방을 가리키는 말이고, 이 인터페이스는 "게임서버의 인터페이스"가 아니라 게임서버로 향하는 NPC 서버의 아웃바운드 포트다. 이 한 문장을 놓치면 3장 이후가 전부 뒤집혀 읽힌다.

목차

지금 이 저장소의 상태

실제로 돌아가는 코드가 있고, 게이트 판정도 대부분 끝났다. 아래 표는 실측 데이터의 게이트 판정을 그대로 옮긴 것이다. 미달·미판정을 통과로 적지 않는다 — 그렇게 적는 순간 게이트가 거짓이 된다.

왜 수치마다 출처를 다는가 이 프로젝트의 계획 단계 추정은 실제로 크게 빗나갔다 — 요청당 입력 토큰이 1,750 가정 → 13,948 실측(8배), 프리베이크 총비용이 $0.94 → $5.12(5.4배)였다(cost_actual.md). 그 경험 때문에 이 저장소는 추정과 실측을 문장 단위로 구분해 적는 규칙을 갖고 있고, 이 책도 같은 규칙을 따른다.
