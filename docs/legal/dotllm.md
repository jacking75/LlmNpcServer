# dotLLM GPLv3 — 배포 경계

> **이 문서는 법무 판단이 아니다.** 기술적 사실과 우리가 취한 조치를 적고,
> **법무가 확인해야 할 질문**을 명시한다. 확인 전에는 상용 배포를 하지 않는다.

## 사실

- **dotLLM 은 GPLv3다.** 로컬 추론(T1)에 쓴다.
- GPLv3는 "결합 저작물(derivative work)" 전체에 같은 라이선스를 요구한다.
  우리 서버가 결합 저작물이 되면 **소스 공개 의무**가 생긴다.

## 우리가 취한 조치

| 조치 | 근거 |
|---|---|
| **NuGet 참조를 두지 않는다** | 인프로세스 링크는 결합 저작물 논란의 중심이다 |
| **별도 프로세스 + HTTP(OpenAI 호환)로만 부른다** | 프로세스 경계 + 표준 프로토콜 |
| **이미지에 넣지 않는다** | `deploy/Dockerfile` 에 dotLLM 바이너리가 없다 |
| **`tools/dotllm/` 은 `.gitignore`** | 저장소에 바이너리를 담지 않는다 |
| **`IChatClient` 추상화를 거친다** | 엔진을 갈아 끼울 수 있다 — 특정 엔진에 묶이지 않는다 |

코드로 강제되는 부분은 `CLAUDE.md` §2.7 과 `ArchitectureTests`(NuGet 의존 검사)다.

## 대안 — llama.cpp (MIT)

`appsettings.Llm.json` 에 `llamacpp-*` 엔진이 이미 있다. **같은 OpenAI 호환 HTTP**라
설정 한 줄로 바뀐다.

| 엔진 | 라이선스 | 비고 |
|---|---|---|
| dotLLM | **GPLv3** | prefill 이 llama.cpp 의 2~5배 느리다 (실측) |
| llama.cpp | **MIT** | decode 는 dotLLM 이 0.8x. continuous batching 있음 |

**실측상 llama.cpp 가 빠르고 라이선스도 느슨하다.** 기본 체인을 llama.cpp 쪽으로 두는 것이
기술적으로도 유리하다 — 다만 그 결정은 운영 환경(GPU·배포 방식)을 아는 사람이 한다.

## 법무가 확인해야 할 질문

> **아래는 전부 미확인이다.** 답이 나오기 전에 상용 배포를 하지 않는다.

1. **별도 프로세스 + HTTP 경계가 GPLv3의 "결합 저작물" 을 피하는가?**
   - 우리 판단: 피한다고 본다(프로세스 분리 + 표준 프로토콜 + 인프로세스 링크 없음).
   - **법무 확인 필요.** 관할과 배포 형태(SaaS vs. 온프레미스)에 따라 달라질 수 있다.
2. **SaaS 로 제공하면 어떤가?** GPLv3에는 AGPL 같은 네트워크 조항이 없지만,
   그 사실을 근거로 삼아도 되는지 확인이 필요하다.
3. **온프레미스로 dotLLM 을 함께 납품하면?** 그때는 배포에 해당한다 —
   GPLv3 사본과 소스 제공 의무가 붙는다. 우리 서버 소스까지 미치는지가 핵심 질문이다.
4. **대안(llama.cpp MIT)으로 기본을 바꾸면 이 질문이 사라지는가?**

## 판정

| 항목 | 상태 |
|---|---|
| 기술적 분리 | **완료** — NuGet 의존 0, 이미지 미포함, HTTP 경계 |
| 법무 확인 | **미실시** — 위 4개 질문에 답이 없다 |
| 상용 배포 가능 여부 | **판정 불가** |

**이 표를 지우지 않는다.** 없는 것을 채우면 판단이 거짓이 된다.
