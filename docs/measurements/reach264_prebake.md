## 1. 도달 집합을 어떻게 골랐나

`bucket_usage.md` §7 의 절차를 **마스터데이터에서 다시 유도**했다. 보고서 값을 옮겨 쓰지 않았다.

```
for each NPC in npc_instances.json (5,000):
    zone = zones[npc.zone]
    pairs[npc.archetype].add( (zone.default_region_state, zone.default_climate) )

도달 버킷 = Σ |pairs[a]| × 시간대 6
```

| 산출 | 값 | `bucket_usage.md` 대조 |
|---|---|---|
| 아키타입 | 40 | 일치 |
| (지역상태, 기후) 쌍 | **44** | — |
| **도달 버킷** | **44 × 6 = 264** | **일치** |
| 조합 2개 이상인 아키타입 | `hunter` · `miner` · `shepherd` · `woodcutter` | **일치** |
| Peace.Fair / Alert.Fair / Peace.Cold / Alert.Cold | 234 / 12 / 12 / 6 | **일치** |

**독립 재유도가 보고서와 완전히 일치했다.**

### 도구 변경은 없었다

`bucket_usage.md` §5 가 예상한 그대로 `--only` 글롭으로 표현된다. 44개 패턴이면 된다.

```
--only "acolyte@*.Peace.Fair" --only "hunter@*.Alert.Fair" --only "hunter@*.Peace.Cold" ...
```

`--plan`(LLM 미호출)으로 **대상 264 버킷**을 먼저 확인한 뒤 실행했다.

## 4. 게이트에 무엇이 움직였나

### 4.1 P4 항목 2 — **미달 → 통과**

| 회차 | 채운 버킷 | 히트율 | 판정 |
|---|---:|---:|---|
| W10 시나리오 B 최소분 | 254 | **76.08 %** | 미달 |
| **이 회차 (도달 집합)** | **195** | **98.67 %** | **통과** |

**버킷 수를 59개 줄였는데 히트율이 22.6 %p 올랐다.**
직전 254개는 시나리오 B 를 겨냥해 War 계열을 채운 것이라 평시 주행에서 대부분 조회되지 않았다.

### 4.2 SiegeTests — 4건 실패 → **2건**

| 테스트 | 이전 | 지금 |
|---|---|---|
| `Siege_OnlyMissedBucketsBecomeLlmWork` | 실패 | **통과** |
| `Siege_RestoresPlansOnPeace` | 실패 | **통과** |
| `Siege_ArchetypesDivergeUnderWar` | 실패 | **실패** |
| `Siege_TownSwapsWithinThreeSeconds` | 실패 | **실패** |

남은 둘은 **"War 인데 아무 플랜도 갈아타지 않았다"** 이고, 원인은 명확하다 —
**도달 집합 A 에는 War 버킷이 없다.** 공성까지 덮으려면 978버킷 집합이 필요하다
(`bucket_usage.md` §5, 추가 약 $1.0).

### 4.3 P3 항목 1·2·3·4 — **여전히 판정되지 않는다**

```
부분 회차의 manifest 다 (생성 완료율 6.8 %). 이 항목은 전량 2880 회차에서만 판정된다
```

`Phase3GateTests.RequireFullRun` 이 막는다. **이것은 결함이 아니라 설계다** —
파일럿 값으로 전량 게이트를 통과시키지 않겠다는 것이고 CLAUDE.md §5 가 정한 태도다.

**그러나 이제 상황이 달라졌다.** 게이트의 분모가 2,880 인데 프로젝트는
`RnD_Report` 권고 2 로 **"전량을 만들지 않는다"** 를 택했다. 그러면 항목 1(완료율 ≥ 95 %)은
정의상 영원히 6.8 % 이고 닫히지 않는다.

> **기준을 바꿔 통과시키지 않았다.** 게이트를 스스로 고쳐 통과시키면 게이트가 거짓이 된다.
> 이 어긋남은 `TASKS.md §3` 에 결정 대기 항목으로 올렸다 — 분모를 "전량 2,880" 에서
> **"선언된 대상 집합"** 으로 바꿀지는 사람이 정할 일이다.

## 5.2 후속 — 공성 확장 회차 (+714 버킷, 같은 날)

§4.2 가 남긴 `SiegeTests` 2건을 닫으려고 **도달 집합 + 공성 = 978** 로 넓혔다.
추가분만 돌렸다 — 이미 만든 264 는 대상에서 빠진다(`--plan` 이 "대상 714 버킷" 확인).

### 978 을 어떻게 유도했나

`scenarios/siege.jsonl` 이 흔드는 존·상태를 그 존의 NPC 에 더한다 (`bucket_usage.md` §7).

| 존 | 지역상태 | 기후 |
|---|---|---|
| `town_center` | Peace · **Alert** · **War** | Fair · **Storm** |
| `gate_east` | Peace · **War** | Fair |
| `town_east_market` | Peace · **Alert** | Fair |

| 산출 | 값 | `bucket_usage.md` 대조 |
|---|---|---|
| A (평시) | 264 | 일치 |
| **B (공성 포함)** | **978** | **일치** |
| 추가분 | 714 (119쌍 × 6) · 영향 아키타입 30종 | — |

### 결과

| 항목 | 264 회차 | **714 회차** | 누계 |
|---|---:|---:|---:|
| 생성 성공 | 195 (73.9 %) | **523 (73.2 %)** | **718** |
| 인접 재사용 | 3 | 46 | 49 |
| 폴백 | 66 | 145 (20.3 %) | 211 |
| 비용 | $0.3727 | **$0.6990** | **$1.0717** |
| 소요 | 96.9 s | 177.6 s | 274.5 s |
| 프롬프트 캐시 | 45.4 % | **69.2 %** | — |
| 429 | 0 (최대 24) | 0 (최대 **32**) | — |

**캐시 적중률이 45.4 % → 69.2 % 로 올랐다.** 회차가 길어 프리픽스가 더 오래 살아 있었고,
AIMD 가 상한 32 까지 올라가 같은 시점에 더 많은 요청이 같은 캐시를 물었다.
429 는 여전히 0 이라 **상한 32 도 아직 천장이 아니다.**

### 게이트

| 항목 | 264 회차 | **718 버킷** |
|---|---|---|
| P4 항목 2 — 시나리오 A 히트율 | **98.67 % 통과** | **98.67 % 통과** (변동 없음) |

§4.1 이 말한 "개수가 아니라 어느 버킷이냐" 가 반대 방향으로도 확인된 셈이다.

### 남은 것 하나 — manifest 는 스토어 총계가 아니라 회차 기록이다
