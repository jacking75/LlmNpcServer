# 오써링 공수 정산

> `tools/calc_authoring.cs` 가 만든다. 손으로 고치지 않는다.
> docs/15 §7 — 축 A(절감률)와 축 B(커버리지 배수)를 둘 다 낸다.

| 항목 | 값 |
|---|---|
| 측정일 | 2026-07-27 KST |
| 폴백 플랜 (사람 경로의 결과물) | 40개 |
| 버킷 (LLM 경로의 결과물) | 2880개 |
| 프리베이크 회차 | 2026-07-26T-W8-pilot288 · `poe-gemini-2.5-flash-lite` |
| 회차 대상 | 288 / 2880 버킷 |
| 그중 생성 성공 | 195 |
| 회차 wall-clock | 115s |
| 회차 비용 | $0.5119 |

## 0. 측정되지 않은 입력

**여기 적힌 것은 실측이 아니다.** 아래 숫자는 가정이고, 결론이 가정에 얼마나 매여 있는지는 §1 의 민감도 표로 본다.

| 입력 | 상태 |
|---|---|
| 수작성 분/플랜 | **미측정.** `authoring_time.jsonl` 40행이 전부 `baseline_eligible=false` 다 — 코딩 에이전트가 만든 플랜이라 사람의 작성 시간이 아니다 |
| 검수 분/플랜 | **미측정.** `review_W8.jsonl` 이 없다 (T3-18 미착수). 가정 2.0분 |
| 프롬프트 설계 공수 | **미측정.** W5~W6 의 실소요를 기록한 파일이 없다 |
| 프리베이크 전량 | **외삽.** 288버킷 회차를 10.0배 해서 전량으로 늘렸다 |

## 1. 축 A — 절감률 (같은 결과물 2,880개)

LLM 경로 = 프롬프트 설계(1회) + 프리베이크 + 검수 + 수정.
수작성 경로 = 2,880 × 평균 작성분.

프리베이크 전량은 **0.32시간 · $5.12** 이고 사람 시간이 들지 않는다 (기계가 돈다). 사람 시간은 프롬프트 설계와 검수뿐이다.

전량 검수는 2880 × 2.0분 = **96시간** 이다.

| 수작성 분/플랜 → | 15분 | 30분 | 60분 | 
|---|---|---|---|
| 수작성 2,880개 (시간) | 720 | 1440 | 2880 | 
| LLM 경로 (설계 20h 가정) → 절감률 | 116h · 84 % | 116h · 92 % | 116h · 96 % | 
| LLM 경로 (설계 40h 가정) → 절감률 | 136h · 81 % | 136h · 91 % | 136h · 95 % | 
| LLM 경로 (설계 80h 가정) → 절감률 | 176h · 76 % | 176h · 88 % | 176h · 94 % | 

> 프롬프트 설계는 **1회성**이다. 버킷이 2,880 → 28,800 이 되면 설계 공수는 그대로이고
> 검수만 늘어난다 — 표의 절감률은 버킷 수가 커질수록 좋아진다.

## 2. 축 B — 커버리지 배수 (같은 비용)

**사람은 애초에 2,880개를 만들지 않는다.** 현실의 대안은 "2,880개 수작성" 이 아니라
**"40개만 만들고 나머지는 포기"** 다. 실제로 이 저장소의 폴백이 정확히 그 40개다.

| 항목 | 사람 경로 | LLM 경로 |
|---|---|---|
| 결과물 | 40개 (아키타입당 1개) | 2880개 (아키타입 × 시간대 × 지역상태 × 기후) |
| 상황 해상도 | 아키타입만 | 아키타입 × 72 상황 |
| 커버리지 배수 | 1× | **72×** |
| 기계 시간 | - | 0.32h |
| 비용 | - | $5.12 |

축 B 가 더 정직하고 더 설득력 있다 (docs/15 §7). 축 A 는 아무도 하지 않을 작업과
비교하는 것이고, 축 B 는 실제로 있었던 선택지와 비교하는 것이다.

## 3. 이 정산을 확정하려면

| 필요한 것 | 어디서 |
|---|---|
| 사람이 폴백 40개를 다시 짜고 시간을 기록 | `authoring_time.jsonl` 의 `minutes`·`baseline_eligible=true` |
| 검수 40건 실측 | T3-18 — `review_W8.jsonl` |
| W5~W6 프롬프트 설계 실소요 | 기록 파일 신설 필요 |
| 프리베이크 전량 회차 | T2-19 — 지금 manifest 는 파일럿이다 |

## 4. 다시 돌리는 법

```
dotnet run tools/calc_authoring.cs -- --date "2026-07-27 KST"
dotnet run tools/calc_authoring.cs -- --minutes-per-plan 20,45 --prompt-design-hours 30
```
