`docs/11 §11` 체크리스트 8항목. 자동화는 `tests/Npc.Tests/Gates/Phase1GateTests.cs` 에 있고,
아래 수치는 그 테스트와 같은 조건을 `Npc.Host` 로 직접 돌려 받은 것이다.

- 측정일: 2026-07-26
- 커밋: `T1-62`
- 기기: Windows 11 Pro 26200, .NET 10, Release, ServerGC
- 명령:
  ```powershell
  dotnet run -c Release --project src/Npc.Host -- `
      --loopback --npcs 5000 --time-scale 600 --days 1 --max-speed --no-dashboard
  ```
  `--max-speed` 는 10Hz 실시간 페이싱을 끈다. 게임 로직은 여전히 `Tick` 만 보므로
  결과는 페이싱 유무와 무관하다 — 벽시계는 호스트 계측에만 있다.

## 4. 읽을 때 주의할 것

**합성 타임아웃 17%는 Sim 의 특성이지 결함이 아니다.** `Npc.Sim` 은 게임서버 대역이라
`Craft`·`Trade` 같은 액션 중 일부를 처리하지 않고 흘린다(`SimWorld.Unhandled`). 응답이
없으면 실행기가 로컬에서 `ActionFailed(Timeout)` 을 합성해 진행을 재개한다 —
`docs/02 §1` 이 요구하는 바로 그 경로다. 이 경로가 상시 돌고 있다는 뜻이므로 오히려 좋다.
실제 게임서버가 붙으면 이 비율은 드롭률만큼으로 떨어진다.

**인지 스캔이 정확히 150인 것은 상한에 붙었다는 뜻이다.** 플레이어 봇 20마리가 POI 를
돌며 수백 마리를 LOD 0 으로 끌어올린다. 상한이 없으면 612까지 올라간다(`docs/11 §4`).
잘린 몫은 다음 틱에 이어 보므로 굶는 NPC 는 없고, 판정 주기만 늘어난다.

**`gen0 0` 은 프로세스 전역 카운터다.** 같은 프로세스에서 도는 Sim 이 이벤트를 할당하므로
Sim 부하가 커지면 이 값이 0 이 아닐 수 있다. 틱 루프만 격리한 측정은
`Runtime_NoGen0GcInTickLoop` 이며, 거기서는 5,000 NPC · 1,000틱 동안 스레드 할당 델타가
정확히 0 바이트다. `bytes/tick` 이 그 값을 상시로 보여준다.

**`--max-speed` 는 처리량 측정이지 지연 측정이 아니다.** 실서비스는 10Hz 페이싱으로 돌고,
그때 틱 사이 여유는 100ms − 2.4ms = 97.6ms 다.
