## 2. P1 기준선 대비 — NPC 5,000 · 게임 1일 (1,440틱)

같은 조건(`--loopback --npcs 5000 --time-scale 600 --days 1 --player-bots 20 --max-speed`)이다.

| 지표 | P1 (`P1_gate.md`) | **P4** | 목표 |
|---|---|---|---|
| 틱 p50 | 0.183 ms | **0.231 ms** | ≤ 8 ms |
| 틱 p99 | 2.375 ms | **0.801 ms** | ≤ 20 ms |
| 틱 max | 10.482 ms | **1.045 ms** | — |
| 예산 초과(오버런) | 0 | **0** | 0 |
| 인지 스캔/틱 | 150 | **150** | ≤ 150 |
| 틱당 할당 | 0 B | **0 B** | 0 |
| Gen0 컬렉션 | 0 | **0** | 0 |
| 시퀀스 갭 (N6) | 0 | **0** | 0 |

**p99 와 max 가 P1 보다 낮다. 이 개선을 P4 의 공으로 돌리지 않는다.**
P1 값은 다른 회차에 잰 것이고 같은 세션에서 다시 재지 않았으므로 통제된 비교가 아니다.
`W10_load.csv` 의 같은 셀(`n5000-x600-none-b20-w2-max`)은 1.122 ms 라 회차 간 폭이 이 차이만큼 있다.

### 2.1 이 표가 무엇을 말하고 무엇을 말하지 않는가

**말하는 것 — P4 가 틱 루프에 넣은 것들이 예산을 먹지 않았다.**
이 회차에서 매 틱 실제로 도는 것은 인지 스캔(`CognitionScheduler`) · 점수 계산(`ReplanScorer`) ·
힙 큐 삽입/축출(`ReplanQueue`) · 스냅샷 포착(`ReplanSnapshots`) · 존 전환 예약(`BucketTransition`) ·
LOD 갱신(`LodUpdater`) · 인터럽트 판정(`InterruptMatcher`) 전부다.
큐가 상시 포화(거절 28,943건)라 이 경로들은 쉬지 않는다. 그러고도 틱당 할당이 **0 B** 다.

**말하지 않는 것 — 워커가 돌 때의 값은 아니다.**
게이트 회차는 `--tier none`(`HostOptions.Tier` 기본값)이라 `ReplanWorker` 가 뜨지 않았다.
`models/` 가 비어 로컬 엔진을 띄울 수 없고(§4.2), T2 만 켜면 실비용이 드는데
이 회차의 프리베이크 범위 결정(§4.1)과 어긋난다.

**워커가 틱을 밀지 않는다는 것은 별도 테스트가 본다** — `Worker_RunsOutsideTickLoop` 이
워커를 컴파일러 안에서 동기적으로 붙잡아 둔 채 200틱을 돌리고,
`Handoff_SurvivesConcurrentWorkersAndTicks` 가 워커와 틱을 동시에 굴린다.
구조적으로도 재계획은 별도 `BackgroundService` 에서만 일어나고 틱 루프는
`Volatile.Read` 로 `PendingPlanId` 한 칸을 읽을 뿐이며, `Npc.Runtime → Npc.Llm` 참조는 여전히 없다.

## 3. 항목별 근거

### 3.1 인지 스캔 — 10,000 은 스캐너 단위로 쟀다

호스트로는 잴 수 없다. `masterdata/npc_instances.json` 에 5,000마리뿐이고
(`NpcHost.Create` 가 `Math.Min` 으로 자른다 — `W10_load.csv` 의 `n10000` 셀들이
`npcs_actual=5000` 인 이유가 이것이다), 늘리려 해도 **`masterdata/pois.json` 의 총 정원이 9,238** 이다.
일터별로는 훨씬 적어서 `tools/gen_npcs.cs --population 10000` 은 `smithy` 배정 단계에서 곧바로 멈춘다.

**월드가 5,000 인구로 설계돼 있다.** 정원을 늘리는 것은 마스터데이터 변경(SSOT · CLAUDE.md §2.4)이고
P1 게이트·프리베이크 플랜의 전제를 함께 바꾸는 일이라 게이트 측정을 위해 하지 않았다.

그래서 10,000 은 `CognitionScheduler` 를 직접 세워서 잰다 — 상한은 스캐너의 성질이므로
그 층이 판정의 제자리이기도 하다. `Cognition_IsConstantWithScale`(T1-37)과 같은 방법이며,
인구를 세 밴드에 고르게 흩어 최악을 만든 뒤 300틱의 최댓값을 본다. **150 이다.**

`--scan-cap 0`(무제한)으로 상한을 풀면 같은 조건에서 **614·658 까지 올라간다**
(`W10_load.csv` 의 `n5000`·`n10000` `-uncapped` 셀 — 뒤엣것도 `npcs_actual=5000` 이라
둘 다 5,000 회차이고 그 차이가 회차 간 폭이다). 상한이 실제로 자르고 있다는 뜻이다.

War·Storm·Peace 복귀·킬스위치 T1/T2 를 전부 담고 있는지를 본다.

### 3.4 큐 거절 (항목 10)

게임 2일 · 5,000마리 · `--tier none` 에서 **거절 28,943건**. 그동안:

- 스텝 4,639,066 전진 · 명령 4,711,559 발행 · 오버런 0
- **플랜 없는 NPC 0/5,000** — 전원이 스텝을 가진 플랜을 들고 있다

## 4. 미달 두 항목

### 4.1 캐시 히트율 76.08% (기준 98%)

| 지표 | 값 |
|---|---|
| 히트 | 66,753 |
| 미스 | 20,984 |
| 채워진 버킷 | **254 / 2,880** |
| 콜드 버킷 | 2,626 |

**히트율이 채움 비율에 묶여 있다.** 미스는 폴백 플랜으로 해소되므로 NPC 는 멀쩡히 돌지만
(`PlanStore.Resolve` 는 null 을 반환하지 않는다 · CLAUDE.md §2.6), 게이트 기준인 98% 는
2,880버킷을 전부 채워야 나온다.

**전량 프리베이크를 이 회차에서 돌리지 않은 것은 결정이다.** 사용자가 프리베이크 범위를
"시나리오 B 최소분만" 으로 정했고, 그에 따라 254버킷만 채웠다 (W10 회차 실비용 **$0.1697**,
`planstore/manifest_history.jsonl`).

닫는 방법은 하나뿐이다 — 남은 2,626버킷을 생성한다. `W8_prebake.md §4` 실측
(288버킷 / 115초 / $0.5119, 동시 24)로 환산하면 **약 17.5분 · 약 $4.7** 이다.
그때 이 항목을 다시 잰다.

### 4.2 GPU 사용률 — 미측정

`W10_load.csv` 14회차가 전부 `tier=none` 이다. 그 회차의 `gpu_util_percent` 는 66.8 ~ 73.1% 인데,
**이건 우리 부하가 아니다** — `nvidia-smi` 는 장치 전체를 재고, 이 기기는 측정 시점에 다른 응용이
VRAM 을 7,588 ~ 7,824 MiB(8,188 중) 점유하고 있었다. `W1_env.md §4.3` 이 같은 함정을 기록해 뒀다.

**T1(로컬 dotLLM)을 켜고 잰 회차가 없다.** `models/` 가 비어 있어 (GGUF 미배치 · `.gitignore` 대상)
로컬 엔진을 띄울 수 없었다. `tools/dotllm/dotllm.exe` 는 있다.

그래서 이 항목은 **통과도 실패도 아니라 미측정**이고, 테스트는 그렇게 실패한다 —
`Gate_GpuUnderSixtyPercent` 는 `tier != none && t1_calls > 0` 인 행을 요구하고,
없으면 "장치 전체 사용률을 우리 부하로 읽을 수 없다"고 말하며 멈춘다.
71% 를 그대로 적어 "초과 실패" 로 세는 것도, 0% 로 적어 "통과" 로 세는 것도 거짓이다.

닫는 방법: `models/` 에 8B Q4_K_M 을 놓고 free VRAM ≥ 6,000 MiB 를 확보한 뒤
`--tier t1 --t1-engine <id>` 로 부하 회차를 다시 돌린다 (`W1_env.md §5`).

## 5. 읽을 때 주의할 것

**`--max-speed` 는 처리량 측정이지 지연 측정이 아니다.** 실서비스 10Hz 페이싱 회차
(`n5000-x600-none-b20-w2-paced`)의 p99 는 1.674 ms 이고, 틱 사이 여유는 100 − 1.7 = 98.3 ms 다.

**`gen0 0` 은 프로세스 전역 카운터다.** 같은 프로세스의 Sim 이 이벤트를 할당하므로
Sim 부하가 커지면 0 이 아닐 수 있다. 틱 루프만 격리한 측정은 `host.Metrics.AllocatedInTicks`
(틱 창 안의 스레드 할당 델타)이고 그 값이 **0 B** 다. 이쪽이 더 엄격한 조건이다.

**항목 2·5 가 미달인 상태로 P5 에 들어갈지는 판단이 필요하다.**
둘 다 코드가 아니라 **산출물**이 없어서 못 재는 것이고, 닫는 비용이 §4 에 적혀 있다.
`docs/14 §9` 는 "전 항목 통과" 를 요구하므로 **이 게이트는 아직 열리지 않았다.**
