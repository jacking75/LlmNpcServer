이 장의 한 문장 테스트가 사양이다. 콘텐츠를 되돌리면 문서가 아니라 테스트가 먼저 깨진다. 그리고 그 이름이 곧 "무엇이 깨졌는가" 다.

네 개면 충분한 이유

콘텐츠를 늘리면 테스트도 늘려야 한다는 강박이 생기지만, 실제로 필요한 것은 "내가 넣은 것이 사라지면 알아채는" 최소 집합이다.

① 마스터데이터가 멀쩡한가

[Fact]
public void MasterData_PassesEveryRule()
{
    MasterDataValidationReport report =
        MasterDataValidator.Validate(MasterDataDir, new MasterDataValidationOptions(null));

    string detail = string.Join(
        Environment.NewLine,
        report.Violations.Select(v => $"{v.Code}  {v.Detail}"));

    Assert.True(report.IsValid, $"검증 위반 {report.Violations.Length}건{Environment.NewLine}{detail}");
}

실패 메시지에 위반 목록을 통째로 넣는다. "Assert.True 실패" 만 뜨면 CI 로그를 보고도 뭘 고쳐야 할지 모른다. 4장에서 본 그 메시지들이 그대로 나오게 한다.

④ 와이어 드리프트

[Fact]
public void Wire_CommandRoundTripsWithoutLoss()
{
    var original = new NpcCommand
    {
        Kind = NpcCommandKind.Interact, Npc = new NpcId(4321),
        IssuedAt = new Tick(987_654), Correlation = new CorrelationId(555),
        Priority = CommandPriority.Critical,
        TargetPoi = new PoiId(244), TargetNpc = new NpcId(11),
        Item = new ItemId(83), Amount = -7, Flags = 3,
    };

    NpcCommand round = WireCommand.From(original).To();

    Assert.Equal(original.Amount, round.Amount);   // 부호가 살아야 한다
    ...
}
필드마다 다른 값을 넣는다 전부 같은 값(예: 1)을 넣으면 매핑이 뒤바뀌어도 통과한다. Amount 에 음수를 넣는 것도 같은 이유다 — InventoryChange 는 부호가 있고, uint 으로 잘못 매핑하면 여기서만 잡힌다.

이 책을 마치며

1부 — 켰다

LLM 0회 호출로 명령 1만 건. NPC 한 마리의 하루를 끝까지 따라갔고, 소켓으로 3프로세스를 붙였다. 코드 0줄.

2·3부 — 만들고 흔들었다

아이템·POI·플랜·직업·인터럽트·액션을 넣었다. 아홉 가지로 깨뜨려 보고 명령을 절반 버려 봤다. JSON 이 거의 전부였다.

4·5·6부 — 붙이고 지켰다

링크와 게임서버를 직접 썼고, LLM 을 켜고, 실패를 읽고, 부하로 재고, 테스트로 못 박았다.

가장 중요한 한 줄 이 책의 모든 수치는 실제로 돌려서 얻은 것이다. 안 돌린 것은 안 돌렸다고 적었고, 추정과 실측을 문장 단위로 구분했다. 당신의 프로젝트에서도 같은 규칙을 지키면, 1년 뒤에 이 표를 다시 볼 때 그 표를 믿을 수 있다.
