패치 9종이 전부 예상한 규칙에 걸렸다.
이 장의 한 문장 한 곳을 고쳤는데 규칙이 둘 걸리는 경우가 있다. 마스터데이터는 독립된 설정 파일 11개가 아니라 서로 물려 있는 하나의 그래프다. 대장장이를 8배로 늘리면 인구 가중치(V5)만 깨지는 게 아니라 대장간 정원(V10)도 같이 깨진다.

먼저 — 11개 파일의 지도

작성 순서 world_flags → items → actions → zones → pois → archetypes → context_buckets → interrupts → fallback_plans → prompt → npc_instances
이 순서를 지키지 않으면 계속 되돌아온다. 5장에서 아이템을 먼저 넣고 POI 를 나중에 넣는 이유가 이것이다.

검증 규칙 V1~V11

규칙무엇을 보는가어긴 예
V1파일 안에서 code·id·bit 가 유일한가두 아키타입이 같은 code
V2플래그 참조가 world_flags.json 에 있는가POI 가 AtBakery 를 세운다
V3poi·item·zone·action 참조가 실재하는가POI 가 없는 존을 가리킨다
V4allowed_actions 가 카탈로그 안에 있는가대장장이에게 Fly 를 허용
V5population_weight 합이 1.0 (±0.001)인가한 직업만 8배로
V6total_keys = 아키타입 × 6 × 4 × 3 인가시간대를 하나 지운다
V7모든 아키타입에 폴백이 있고 loop:true 인가폴백 id 를 바꾼다
V8폴백이 그 아키타입의 허용 액션만 쓰는가목동에게 Mine
V9프롬프트 프리픽스 ≥ 4,096 토큰인가LLM 을 켜야 판정된다 (지금은 SKIP)
V10일터·주거 정원이 인구를 감당하는가대장간 64석에 대장장이 495명
V11존 그래프가 대칭이고 POI 가 도달 가능한가인접을 한 방향만 남긴다
V 규칙이 전부가 아니다 검증기는 세 겹이다. 로더(파일이 읽히는가 · 첨자가 맞는가) → V1~V11(참조와 총합) → 플랜 4단 검증기(Schema · Vocabulary · Coherence · DryRun). 출력에 FAIL LOAD 가 뜨면 앞의 둘 중 하나, FAIL V5 처럼 번호가 붙으면 가운데다. 6장에서 마지막 것을 만난다.

samples/ch04_break/break.ps1 — 패치 하나의 정의 
@{
    key = 'v5'; expect = 'V5'
    title = '인구 가중치 합이 1.0 이 아니다 — 대장장이를 8배로'
    file = 'archetypes.json'
    from = "`"population_weight`": 0.012`n    },`n    {`n      `"id`": `"carpenter`""
    to   = "`"population_weight`": 0.099`n    },`n    {`n      `"id`": `"carpenter`""
    why  = '가중치는 인구 배분표다. 합이 1이 아니면 몇 마리를 만들지가 정해지지 않는다'
}

JSON 을 파싱해서 다시 쓰지 않고 원문을 그대로 찾아 바꾼다. 파싱해 다시 쓰면 서식이 통째로 흐트러져서, git diff 로 "내가 무엇을 고쳤나"를 못 읽게 된다. 실습에서도 실무에서도 같은 이유로 그렇게 한다.

여기서 볼 것 넷

  1. 메시지가 무엇을 어떻게 고치라고 말해 준다

    "1.087 인데 1.0 ±0.001 이어야 한다" · "64 인데 495 다" · "'blacksmith' 와 'carpenter'". 규칙 번호만 던지고 끝나지 않는다. 2부 내내 이 메시지를 읽는 것이 일이 된다.

  2. 한 곳을 고쳤는데 둘이 걸린다 v3 · v5

    POI 하나를 없는 존으로 보냈더니 참조(V3)와 도달 가능성(V11)이 같이 깨졌다. 대장장이를 8배로 늘렸더니 가중치(V5)와 정원(V10)이 같이 깨졌다.
    이것이 "콘텐츠 하나를 고칠 때 무엇까지 따라가야 하는가"의 답이다 — 검증기가 대신 따라가 준다.

  3. 실패는 경고가 아니라 기동 실패다

    validate 는 종료 코드 1로 끝나고, 서버도 같은 데이터로는 뜨지 않는다. "경고를 내고 계속 도는" 선택지를 안 만든 이유는 콘텐츠가 반쯤 어긋난 채 도는 서버가 안 도는 서버보다 훨씬 비싸기 때문이다.

  4. 9종이 전부 서로 다른 규칙에 걸렸다

    하나라도 조용히 통과했다면 그게 이 저장소의 구멍이고, 보고할 거리다. 스크립트가 MISS 로 표시한다.

정적 검증의 한계

검증기가 전부 잡아 주지는 않는다. 안 걸리는데 런타임에서 증상이 나는 종류가 있다.

고침검증런타임 증상
duty_hours 없이 Guard·Patrol 을 허용 통과 재계획 큐가 포화된다. OnDuty 를 세우는 것은 duty_hours 뿐인데, 인지 스캔이 매 틱 "근무 중이어야 하는데 아니다"로 읽는다
POI 를 늘리고 거리표를 안 굽는다 LOAD 에서 걸린다 — (5장에서 직접 본다)
플랜의 전제조건이 성립 불가 Coherence 에서 걸린다 — (6장에서 직접 본다)
그래서 확인 3단이다 검증만으로 끝내지 않고 짧게 돌려서 관측까지 하는 이유가 이것이다. check.ps1 의 ②·③단계가 위 표의 왼쪽 두 줄을 잡는다.
