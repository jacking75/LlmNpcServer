③ 실습 골격 ① — lab.ps1

마스터데이터 사본을 뜨고, 원본과 비교하고, 지운다. 하는 일은 그게 전부다. 전체 코드는 samples/lab.ps1 에 있고 약 150줄이다. 핵심은 세 갈래뿐이다.

samples/lab.ps1 — 핵심 부분 
$root    = Split-Path -Parent $PSScriptRoot   # 저장소 루트
$source  = Join-Path $root 'masterdata'       # 원본. 읽기만 한다
$labRoot = Join-Path $root 'lab'              # 사본이 사는 곳

switch ($PSCmdlet.ParameterSetName) {

    'New' {                                    # 사본을 뜬다
        $dest = Join-Path (Join-Path $labRoot $New) 'masterdata'
        Copy-Item -Path $source -Destination $dest -Recurse
    }

    'Diff' {                                   # 무엇을 고쳤는지 본다
        $a = Get-HashMap -Dir $source          # 상대경로 -> SHA256
        $b = Get-HashMap -Dir $dest
        # 양쪽에 다 있는데 해시가 다르면 수정, 한쪽에만 있으면 추가/삭제
    }

    'Drop' {                                   # 지운다
        Remove-Item -Path (Join-Path $labRoot $Drop) -Recurse -Force
    }
}

-Diff 를 파일 해시로 비교하는 이유는, 마스터데이터 JSON 이 수천 줄짜리라 줄 단위 diff 를 눈으로 못 읽기 때문이다. 실습 중에 필요한 답은 "어느 파일을 건드렸나" 하나다.

④ 실습 골격 ② — check.ps1

이 책의 모든 장은 같은 방식으로 결과를 확인한다. 검증 → 실행 → 판정 3단이다. 매번 세 명령을 따로 치는 대신 하나로 묶는다.

samples/check.ps1 에서 눈여겨볼 곳은 두 군데다.

samples/check.ps1 — ② 실행이 왜 이렇게 빠른가 
if ($RealTime) { $runArgs += @('--port', $Port) }
else           { $runArgs += @('--max-speed', '--no-dashboard') }

--max-speed 는 10Hz 페이싱을 하지 않는다. 평소에는 1틱마다 100ms 를 기다리지만, 이 옵션을 주면 최대 속도로 돈다 — 게임 하루(1,440틱)가 실시간 2초에 끝난다. 측정과 회귀 확인은 이걸로 하고, 눈으로 볼 때만 -RealTime 을 준다.

samples/check.ps1 — ③ 판정 기준 
$rows = @(
    @{ n = '틱 p99';          v = "$p99 ms";  ok = ($p99 -le 20);      crit = "≤ 20 ms" },
    @{ n = '틱당 할당';        v = "$bytes B"; ok = ($bytes -eq 0);     crit = "= 0 B" },
    @{ n = '예산 초과 틱';     v = "$overruns"; ok = ($overruns -eq 0); crit = "= 0" },
    @{ n = '명령 드롭 (링크)'; v = "$dropLink"; ok = ($dropLink -eq 0); crit = "= 0" },
    @{ n = '명령 드롭 (Sim)';  v = "$dropSim";  ok = ($dropSim -eq 0);  crit = "= 0" },
    @{ n = '이벤트 이월';      v = "$backlogs"; ok = ($backlogs -eq 0); crit = "= 0" }
)

이 여섯 줄이 이 제품의 수용 기준이다. 전부 종료 요약 한 줄에서 뽑아낸다. 각 항목이 왜 이 값이어야 하는지는 나오는 장에서 하나씩 설명한다 — bytes/tick = 0 은 19장, 드롭 0 은 11장, 이월 0 은 13장이다.

여기서 배우는 것 셋

① 실행 단계까지 못 간다. 이 제품은 마스터데이터 검증 실패를 경고로 처리하지 않는다 — 기동 실패다. "경고를 내고 계속 도는" 선택지를 안 만든 이유는, 콘텐츠가 반쯤 어긋난 채 도는 서버가 안 도는 서버보다 훨씬 비싸기 때문이다.

② 숫자 하나를 고쳤는데 규칙 두 개가 걸렸다. V5(인구 가중치 합)만 깨진 게 아니라 V10(일터 정원)도 같이 깨졌다 — 대장장이가 8배로 늘면서 대장간 정원 64를 훌쩍 넘겼기 때문이다. 마스터데이터는 서로 물려 있다. 이 연쇄가 4장의 주제다.

③ 실패 메시지가 무엇을 어떻게 고치라고 말해 준다. "1.087 인데 1.0 ±0.001 이어야 한다"까지 알려 준다. 이런 메시지를 읽는 것이 2부 내내 하게 될 일이다.

알아 둘 것 하나 위처럼 값이 어긋난 경우는 V 규칙이 깔끔하게 잡는다. 그런데 JSON 문법 자체가 깨진 경우(파일을 중간에서 잘라 버린 경우 등)는 검증기까지 가기 전에 파서가 먼저 죽어서 System.Text.Json.JsonReaderException 과 스택 트레이스가 그대로 나온다. 어느 쪽이든 기동은 실패하니 안전에는 문제가 없지만, 메시지가 갑자기 영어 스택 트레이스로 바뀌면 그건 문법 오류라는 신호다.
