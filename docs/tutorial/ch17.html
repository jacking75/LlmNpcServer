소량으로 굽는다

예산 상한을 먼저 건다 --budget-usd 없이 시작하지 않는다. 프리베이크는 수천 번 호출하는 루프이고, 프롬프트나 마스터데이터가 잘못돼 전부 실패하는 회차도 있다. 상한이 있으면 그 회차의 손실이 상한에서 멈춘다.
터미널 — 12건만 
PS> $env:OPENROUTER_API_KEY = "..."
PS> dotnet run -c Release --project tools/Npc.Prebake -- `
      --masterdata ./masterdata --out ./planstore `
      --tier T2 --model openrouter-gemini-2.5-flash-lite `
      --archetypes blacksmith,farmer --limit 12 --budget-usd 0.10 --concurrency 4
옵션무엇을
--budget-usd먼저 건다. 넘으면 멈춘다
--limit몇 건까지. 실습은 12면 충분하다
--archetypes특정 직업만. 내가 7장에서 만든 직업만 굽고 싶을 때
--only · --stride버킷을 골라내거나 건너뛰며 샘플링
--concurrency기본 8. AIMD 초기값이다 — 429 를 재고 올린다
--resume중단된 회차를 이어서
--print-prefix호출 없이 프리픽스와 토큰 수만 본다
--dryrun-sample4단 DryRun 검증의 표본 수

확인기준왜
프리픽스 토큰≥ 4,096Gemini 3.x · Claude Haiku 4.5 의 프롬프트 캐시 최소 임계. 미만이면 캐시가 아예 안 걸린다
SHA 유니크 수12 이상이면 요청마다 프리픽스가 달라진 것 — 캐시 전면 미적중

실측 요청당 입력 토큰이 13,948 이고 그중 11,967 이 프리픽스다. 프리픽스가 고정이라 제공사 캐시가 접두 일치로 걸리고, prefill 이 85~88 % 감소한다.

반대로 말하면 — 프리픽스에 동적 값이 하나라도 섞이면 이 승리가 통째로 사라진다. 그래서 프리픽스는 기동 시 1회 조립하고 이후 불변이고, 재시도 피드백은 서픽스에만 넣는다.

확인한다

  • read-manifest.ps1 이 masterdata 해시가 같다고 판정한다
  • --print-prefix 의 SHA 가 manifest.prefix_hash 와 같다
  • 프리픽스가 4,096 토큰 이상
  • (키가 있으면) 12건을 구운 뒤 planstore/plans/ 에 파일이 생긴다
  • (키가 있으면) 다시 돌렸을 때 /metrics 의 cache.hitRate 가 오른다
  • 구워진 플랜 JSON 이 사람이 읽을 수 있는 모양이다 — 6장에서 손으로 쓴 것과 같은 스키마

되돌린다 — 프롬프트 회차 (C-03)

system_rules.md 한 줄을 고치면 2,880 버킷이 전부 미적중된다. 예전에는 새 회차가 옛 회차를 덮었다 — 되돌리려면 다시 구워야 했고 그것은 $5 와 5분이다. 지금은 플랜이 프리픽스 SHA 별 폴더에 쌓인다. 

planstore/
  pinned/                  ← 공유. 사람이 검수한 것이라 프리픽스와 무관하다
  prefix/10e852a3.md       ← 그 회차의 프리픽스 전문. 사람이 읽는다
  10e852a3/plans/          ← 지금 프롬프트로 구운 것
  10e852a3/manifest.json
  56a0c601/plans/          ← 이전 프롬프트로 구운 것. 그대로 남는다
하고 싶은 일어떻게
되돌린다git checkout <이전 커밋> -- masterdata/prompt/. SHA 가 이전 값이 되고 그 폴더가 자동 선택된다 — 다시 구울 일이 없다
되돌리지 않고 비교만--planstore-sha 56a0c601. 진단용이다 — 운영에서는 프롬프트를 되돌리는 쪽이 정직하다. 그래야 만들어진 플랜과 지금 쓰는 프롬프트가 같아진다
어떤 프롬프트로 구웠나planstore/prefix/<sha8>.md 를 연다. 머리말에 prompt_version 과 SHA 전문이 있다
회차에 이름을 붙인다masterdata/prompt/prompt_manifest.json 의 prompt_version 을 올리고 changelog 에 한 줄
라벨은 프리픽스에 안 실린다 prompt_manifest.json 을 고쳐도 프리픽스 SHA 는 안 바뀐다. 라벨을 해시에 넣으면 "설명을 고쳤더니 캐시가 전부 미적중" 이 되고, 그러면 아무도 설명을 안 고친다. 신원은 SHA 이고 라벨은 그 SHA 를 사람이 부르는 이름이다 — 라벨을 안 올리고 프롬프트만 고치는 일이 있으므로, 비교에 쓸 것은 언제나 SHA 다.
핀은 회차마다 복사하지 않는다 pinned/ 는 루트에 하나뿐이다. 사람이 검수한 플랜이고 프리픽스가 바뀌었다고 그 검수가 무효가 되지는 않는다 — 무효 판정은 PlanStoreValidator 가 마스터데이터 기준으로 따로 한다. 회차마다 복사하면 어느 쪽이 진짜인지 모르게 된다.
