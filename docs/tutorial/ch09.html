2부 · 세계를 바꾼다

9장 · 새 행동을 추가한다 — 액션 카탈로그 37 → 38

2부에서 파급이 가장 큰 변경이다. 액션 하나를 넣으면 카탈로그·아키타입·플랜만 바뀌는 게 아니라 프롬프트 프리픽스가 바뀌고, 그 순간 미리 구워 둔 플랜이 전량 무효가 된다. 그 무효화를 해시로 눈으로 확인한다.

난이도 ★★★★ 70분 LLM 불필요 사본에서 한다

무엇을 만드나

Tend — 가축과 벌통, 작물을 돌보는 행동을 만든다. 뭔가를 생산하지는 않고 ResourceDepleted 를 걷어낸다.

이 장이 끝나면 — 프리픽스가 얼마나 흔들렸는지 숫자로 나온다 
① 고치기 전 프리픽스
     --- Full: 13488 tok · sha 56a0c601f48392e0
     action_catalog     6182

⑥ 고친 뒤 프리픽스
     --- Full: 13602 tok · sha 0d8cf2bf8bbbd3a8
     action_catalog     6291

   토큰  13488 → 13602  (+114)
   SHA   56a0c601f48392e0 → 0d8cf2bf8bbbd3a8

   프리픽스 SHA 가 바뀌었다 = 미리 구워 둔 플랜이 전량 무효다.
이 장의 한 문장 액션 카탈로그는 손으로 쓴 문서가 아니라 actions.json 에서 생성되는 프롬프트의 본문이다. 그래서 액션을 하나 넣는 것은 LLM 에게 주는 설명서를 다시 쓰는 일이고, 설명서가 바뀌면 그 설명서로 만든 플랜을 믿을 수 없다.

한 줄이 흔드는 곳 넷

① 액션을 쓴다

masterdata/actions.json
{
  "id": "Tend",
  "code": 38,
  "category": "labor",
  "desc": "가축과 벌통, 작물을 돌본다. 무언가를 만들어 내지는 않지만 다음 수확이 가능한
           상태로 되돌린다. 밭에 서 있어야 하고, 지친 상태에서는 할 수 없다.",
  "params": {
    "duration_s": { "type": "int", "min": 60, "max": 1800, "default": 300 }
  },
  "requires":     ["AtField"],
  "requires_any": [],
  "forbids":      ["IsSleeping", "IsExhausted"],
  "grants":       [],
  "clears":       ["ResourceDepleted"],
  "duration": { "kind": "param", "base_s": 0, "per_meter_s": 0, "param": "duration_s" },
  "cost": 2,
  "default_timeout_s": 900,
  "emits": [
    { "command": "SetVisualState", "priority": "Normal", "map": { "Visual": "Working" } }
  ],
  "completes_on": ["NpcActionCompleted"],
  "fails_on":     ["NpcActionFailed"]
}
필드고를 때 생각할 것
code38. 지금 최대가 37이다. 절대 중간에 끼우지 않는다
desc이 문장이 프롬프트에 그대로 실린다. LLM 이 이 액션을 언제 쓸지 이 문장으로 배운다
requires / forbidsCoherence 단이 이걸로 GOAP 시뮬을 돌린다. 느슨하면 이상한 플랜이 통과한다
grants / clears스텝 완료 후의 상태 전이. Tend 는 아무것도 주지 않고 고갈만 걷어낸다
emits게임서버에 실제로 나가는 명령. 여기가 비면 아무 일도 안 일어난다
completes_on어떤 이벤트를 완료로 칠 것인가. 안 오면 timeout_s 가 대신 끝낸다

emits.map 의 문법

값뜻예
"$param"플랜 스텝의 args 에서 가져온다"Amount": "$count"
"$home" "$workplace" "$self" "$zone"NPC 인스턴스에서 바인딩"TargetPoi": "$workplace"
"$first:Flag"그 플래그를 세우는 인벤토리 첫 아이템Eat · Drink
그 외 문자열아이템 id 또는 열거값 리터럴"Visual": "Working"
숫자정수 리터럴"Amount": 1
왜 SetVisualState 인가 게임서버의 명령 종류는 12개로 고정이다 (NpcCommand.Kind). 새 액션을 만든다고 새 명령을 만들지 않는다 — 기존 12개 중 하나로 표현한다. Tend 는 자원을 옮기지도 대화하지도 않으니 "일하는 겉모습"만 내보내면 충분하다. Rest·Bathe 가 같은 방식이다.
명령 종류를 늘려야 하는 변경은 게임서버 팀과의 계약 변경이고, 그건 13장의 영역이다.

① 프롬프트 캐시가 통째로 미적중이 된다. 제공사의 프롬프트 캐시는 접두 일치로 걸린다. 프리픽스 첫 글자부터 달라졌으니 이전 캐시는 하나도 안 맞는다. 실측 기준 prefill 이 85~88 % 절감되던 것이 첫 요청들에서 사라진다.

② 이미 구워 둔 플랜의 근거가 사라진다. 그 플랜들은 Tend 를 모르는 카탈로그로 만들어졌다. 문법적으로는 여전히 유효하지만 "지금 카탈로그로 다시 만들면 다른 답이 나오는" 플랜이다.

판단은 사람이 한다. 액션 하나 추가에 2,880건을 다시 굽는 것이 늘 옳지는 않다 — 실측 기준 전량 프리베이크가 $5.12 다. 17장에서 "무엇부터 다시 구울까"를 정하는 법을 본다.

프리픽스를 무효화하려면 앞에 넣는다 캐시 무효화용 주석을 프리픽스 뒤에 붙이면 캐시가 안 깨진다. 접두 일치라 앞부분이 같으면 그대로 적중한다. 그러면 "무효화했다고 믿는데 실제로는 옛 캐시를 쓰는" 상태가 되고 측정이 거짓이 된다. 무효화는 반드시 프리픽스 맨 앞이다.

왜 상한이 40개인가

액션을 하나 더 넣으면얼마나
프롬프트 프리픽스+109 토큰 (실측). 40개면 카탈로그만 6,500 토큰대

새 액션 요청을 받았을 때의 기준 ① 기존 액션의 파라미터로 흡수할 수 있나? Tend 도 사실 Work 의 파라미터 하나로 표현할 수 있었다. ② 하나를 뺄 수 있나? 안 쓰이는 액션이 있는지 /metrics 의 액션 분포로 확인한다. ③ 그래도 필요하면 이 장의 절차를 밟고, 프리픽스 무효화를 감수한다.
