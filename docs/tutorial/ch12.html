이 장의 한 문장 링크는 갈아 끼우는 부품이다. 새 링크를 넣는 데 고친 곳은 셋뿐이고, 그중 둘은 배선(enum 값 하나, switch case 하나)이다. Npc.Runtime·Npc.Planning·Npc.Core·Npc.Contracts 의 diff 는 0줄이다.

경계는 다섯 개뿐이다

src/Npc.Contracts/IGameServerLink.cs
public interface IGameServerLink : IAsyncDisposable
{
    void      Enqueue(in NpcCommand command);        // 쌓는다. 반환값 없음 (N1)
    ValueTask FlushAsync(CancellationToken ct);      // 내보낸다 (N8)

    ChannelReader<GameEvent> Events { get; }         // 받는다
    LinkState State { get; }
    LinkStats Stats { get; }

    event Action<LinkState>? StateChanged;
}
규칙여기서 어떻게 드러나는가
N1Enqueue 가 void 다. 보낸 쪽은 성공 여부를 모른다. 결과는 Events 로만 온다
N8단건 전송 메서드가 없다. Enqueue 로 쌓고 FlushAsync 로 한 번에 내보낸다
N5응답을 만들 때 Correlation 을 그대로 돌려준다. 이게 없으면 어느 명령의 답인지 모른다
N6내보내는 이벤트마다 Sequence 를 순증으로 매긴다
왜 반환값을 금지했나 Task<bool> SendAsync(...) 하나만 있으면 편해 보인다. 그런데 그 메서드는 네트워크 왕복을 기다린다. 틱 루프가 그것을 await 하는 순간 10Hz 예산 20ms 안에 RTT 가 들어와야 하고, 게임서버가 한 번 느려지면 NPC 서버 전체가 밀린다.

그래서 편의를 금지하는 규칙을 계약에 박고, 테스트로 강제한다.

링크를 쓴다

전체는 samples/ch12_console_link/ConsoleGameServerLink.cs 에 있다(약 180줄). 핵심은 셋이다.

① 쌓고 · 내보내고 · 답한다

public void Enqueue(in NpcCommand command)
{
    _pending.Add(command);      // 반환값이 없다 (N1)
    _enqueued++;
}

public ValueTask FlushAsync(CancellationToken ct)
{
    foreach (NpcCommand command in _pending)
    {
        _out.WriteLine(Format(command));
        Respond(command);       // 응답을 합성한다
        _flushed++;
    }

    _pending.Clear();
    return ValueTask.CompletedTask;
}

② 명령 종류마다 어떤 이벤트로 답하나

GameEventKind kind = command.Kind switch
{
    NpcCommandKind.MoveTo  => GameEventKind.NpcArrived,     // 이동은 "도착"
    NpcCommandKind.Spawn   => GameEventKind.NpcSpawned,
    NpcCommandKind.Despawn => GameEventKind.NpcDespawned,
    _                      => GameEventKind.NpcActionCompleted, // 나머지는 "완료"
};

_events.Writer.TryWrite(new GameEvent
{
    Kind        = kind,
    Sequence    = Interlocked.Increment(ref _sequence),   // N6
    OccurredAt  = command.IssuedAt,
    Npc         = command.Npc,
    Correlation = command.Correlation,                    // N5 — 그대로 돌려준다
    Poi         = command.TargetPoi,
});

③ 데코레이터인 이유 — 시간은 누가 미나

여기서 한 번 걸렸다

처음엔 자기 채널만 들고 만들었다. 빌드도 되고 배선도 됐는데 --days 1 이 영원히 안 끝났다.

세계 시간을 미는 것은 링크가 아니라 호스트의 펌프다. 펌프는 게임서버 대역이 없을 때 NullGameServerLink.PushTick() 으로 TickSync 를 넣는데, 우리 링크가 자기 채널만 보면 그 틱이 아무에게도 안 간다. 게임 시계가 안 가니 "게임 1일"이 영원히 안 온다.

그래서 NullGameServerLink 를 감싼다. 안쪽 이벤트를 우리 채널로 옮기고 시퀀스만 다시 매긴다 — RecordingGameServerLink 와 같은 모양이다. 

public ConsoleGameServerLink(NullGameServerLink inner, ...)
{
    _inner = inner;
    _forward = Task.Run(ForwardAsync);   // 안쪽 이벤트를 우리 채널로
}

private async Task ForwardAsync()
{
    await foreach (GameEvent e in _inner.Events.ReadAllAsync())
    {
        // 합성분과 섞이므로 시퀀스는 한 줄기여야 한다 (N6)
        _events.Writer.TryWrite(e with { Sequence = Interlocked.Increment(ref _sequence) });
    }
}
