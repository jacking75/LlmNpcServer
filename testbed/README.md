# 테스트 베드 — 게임서버 대역 + 테스트 클라이언트

NPC 서버가 **실제 소켓 너머의 게임서버**에 붙어 도는 것을 눈으로 보는 자리다.
사양은 [`docs/20_TestBed_Spec.md`](../docs/20_TestBed_Spec.md), 작업 지시서는
[`docs/20_TestBed_TASKS.md`](../docs/20_TestBed_TASKS.md)에 있다.

**이 폴더가 증명하는 것 하나.** 여기서 게임서버·클라이언트·와이어 프로토콜을 통째로 새로 만들었는데
`Npc.Runtime`·`Npc.Planning`·`Npc.Core`·`Npc.Contracts`의 diff가 **0줄**이다.
"게임서버에 붙일 때 NPC 서버 코드가 한 줄도 안 바뀐다"는 주장의 실물이다.

```
┌──────────────┐   TCP 7010 (링크)    ┌──────────────────┐
│  Npc.Host    │◄────────────────────►│ Npc.TestGameServer│
│ (NPC 서버)   │  명령/이벤트 (N1~N8) │  (게임서버 대역)  │
└──────┬───────┘                      └────────┬─────────┘
       │ HTTP 5080                             │ TCP 7020 (클라이언트)
       │ /npc/{id} · /metrics                  │
       │                              ┌────────▼─────────┐
       └─────────────────────────────►│  Npc.TestClient  │
              인스펙터가 직접 폴링     │   (WinForms)     │
                                      └──────────────────┘
```

**클라이언트가 NPC 서버를 직접 보는 이유.** 플랜 id·스텝 번호·월드 플래그는 **게임서버가 알 수 없는
정보**다. 링크에 그런 필드가 없고 있어서도 안 된다(N1·N3). 게임서버를 경유해 중계하면
실제로는 존재하지 않는 결합을 테스트 베드가 만들어 낸다.

## 요구 환경

| 항목 | 요구 |
|---|---|
| OS | **Windows 10/11** — 클라이언트가 WinForms(`net10.0-windows`)다 |
| SDK | .NET 10 SDK |
| LLM | **필요 없다.** 기본이 `--tier none`이라 LLM을 한 번도 부르지 않는다 |
| 프리베이크 플랜 | 있으면 좋고 없어도 된다. 없으면 아키타입 폴백 40개로 돈다 |

## 한 줄로 띄우기

```powershell
./testbed/run_demo.ps1 -Scenario siege
```

게임서버 → NPC 서버 → 클라이언트를 순서대로 띄우고, **Ctrl-C에 셋 다 내린다.**
창을 하나 닫아도 나머지가 따라 내려간다.

| 옵션 | 기본 | 의미 |
|---|---|---|
| `-Scenario day\|siege\|blackout` | `day` | `scenarios/demo_<이름>.jsonl`을 쓴다 |
| `-Npcs N` | 300 | 게임서버와 NPC 서버에 **같은 값**이 간다 |
| `-TimeScale N` | 60 | 데모 시나리오의 틱 좌표가 60 기준이다 |
| `-Tier none\|t1\|t2\|all` | `none` | NPC 서버의 재계획 티어 |
| `-NoBuild` | — | `dotnet build`를 건너뛴다 |

첫 실행은 빌드 때문에 30초쯤 걸린다. 두 번째부터는 `-NoBuild`를 준다.

## 손으로 띄우기

스크립트가 하는 일은 이 셋이다. 터미널 셋에 하나씩 넣는다.

```powershell
# 0) 빌드
dotnet build -c Release

# 1) 게임서버 — 먼저 떠 있어야 한다 (나머지 둘은 재접속을 돌리므로 순서가 어긋나도 죽지는 않는다)
dotnet run -c Release --project testbed/Npc.TestGameServer -- `
    --npcs 300 --time-scale 60 --link-port 7010 --client-port 7020 `
    --scenario testbed/scenarios/demo_siege.jsonl

# 2) NPC 서버
dotnet run -c Release --project src/Npc.Host -- `
    --link tcp --gs-port 7010 --npcs 300 --time-scale 60 --days 0 `
    --tier none --planstore ./planstore --port 5080 --dev-control

# 3) 클라이언트
dotnet run -c Release --project testbed/Npc.TestClient -- `
    --host 127.0.0.1 --port 7020 --npc-http http://localhost:5080
```

**포트.** 7010 링크 · 7020 클라이언트 · 5080 NPC 서버 HTTP(`/dashboard`·`/metrics`·`/npc/{id}`).

**`--npcs`·`--time-scale`·`--zone`은 양쪽이 같아야 한다.** 하나라도 다르면 핸드셰이크에서 거절된다 —
그것이 의도된 동작이다. 첨자가 어긋난 채로 도는 것보다 연결 시점에 죽는 편이 싸다
(어긋나면 대장장이에게 밭을 갈라고 명령하게 되고, 증상은 "가끔 이상하게 행동한다"로만 나타난다).

## 데모 시나리오 3종

`scenarios/` 아래에 있다. 틱 좌표는 **`--time-scale 60` 기준**이고,
그때 게임 1시간 = 600틱 = 실시간 60초다. 시작 시각은 06:00(Dawn).

| 파일 | 실시간 | 볼 것 |
|---|---|---|
| `demo_day.jsonl` | 약 17분 | **주입 이벤트가 0개다.** 시간대가 넘어갈 때(18:00 Evening) 버킷 키가 바뀌어 인스펙터의 plan id가 갈리는 것을 본다. 이벤트 없이 NPC가 하루를 사는 것 자체가 이 프로젝트의 결과물이다 |
| `demo_siege.jsonl` | 4분 | tick 1200에 `town_center`·`gate_east`가 War로 간다. **존 테두리가 빨개지는 순간 그 존의 NPC 전원이 동시에 다른 계획으로 갈아탄다.** tick 2400에 평화로 되돌린다 |
| `demo_blackout.jsonl` | 3분 | T2 → T1 → PlanStore를 600틱 간격으로 끊는다. **볼 것은 "아무 일도 일어나지 않는다"** — NPC는 계속 움직이고 크래시가 없다. 인스펙터의 `PlanKind`가 `bucket` → `fallback`으로 내려가는 것이 성공 신호다 |

**`demo_blackout`은 같은 파일을 양쪽에 준다.** 게임서버는 `KillSwitch` 줄을 무시하고,
NPC 서버는 `KillSwitch` 줄만 처리한다. 틱 번호는 게임서버가 보내는 `TickSync`로 동기화되어 있으므로
같은 틱에 발동한다. `run_demo.ps1`이 양쪽에 알아서 넘긴다.

`--tier none`(기본)에서는 실제로 끊기는 것이 PlanStore 하나다. T2·T1 차단까지 보려면
`-Tier t2`로 돌린다.

## 알려진 한계

**여기 적힌 것은 전부 의도한 것이거나 근거가 있는 미완이다.** 버그로 오해하지 않도록 남긴다.

| 무엇 | 내용 |
|---|---|
| **결정론이 성립하지 않는다** | `docs/15` §3의 "리플레이 100% 일치"는 **루프백 경로의 게이트**다. 소켓 경로에서는 명령이 몇 틱 늦게 도착할 수 있고 그것이 스텝 경계를 바꾼다. **결함이 아니라 사실이다** — 실제 게임서버에 붙으면 원래 그렇다. 결정론이 필요한 회차는 `--loopback`으로 돌리고, 소켓 경로의 재현이 필요하면 `--link record`로 이벤트 열을 기록해 `--link replay`로 되민다 |
| **킬스위치는 링크로 안 간다** | NPC 서버 안쪽 상태이고 `GameEvent`에 그런 종류가 없다 — 만들면 N 규칙을 어긴다. 제어 패널의 버튼은 `POST /control/killswitch`를 직접 부르고, **`--dev-control` 없이 기동한 NPC 서버에는 그 라우트가 아예 없어서** 404다(화면에는 "미연결"로만 나온다). 조건부 401/403이 아니라 **조건부 등록**인 이유는 그쪽이 실수 하나로 열리기 때문이다 |
| **`SkipTime`은 리플레이 대상이 아니다** | 틱을 점프시키면 진행 중인 이동·작업의 만료 시각이 전부 지나가 다음 틱에 한꺼번에 끝난다. 도착 이벤트가 몰려 나가고 NPC들이 순간이동한 것처럼 보인다. **데모 편의 기능이다** — 시나리오 파일로 돌리는 회차에서는 쓰지 않는다 |
| **고장 주입 슬라이더가 시작 옵션과 겹친다** | 제어 패널의 슬라이더는 `--fail-rate`/`--drop-rate`를 **대체하지 않고 그 앞에 선다.** 둘 다 주면 실효 확률이 겹쳐 걸린다(0.1 + 0.3 → 약 0.37). 데모 기본이 0이라 실제로는 슬라이더 값이 전부다. 떼지 않은 이유는, 떼면 `--fail-rate`로 시작한 회차가 클라이언트가 붙는 순간 조용히 무고장이 되기 때문이다 |
| **`InCombat` 테두리가 안 켜진다** | 스냅샷의 `StateFlags` bit2를 채우는 곳이 없다. 전투 상태를 들고 있는 자리가 게임서버 어디에도 없어서 비웠다 — HP 같은 것으로 흉내내면 **화면이 거짓말을 한다.** 증상은 붉은 테두리가 안 보이는 것 하나뿐이다 |
| **상태바의 `npc` 틱이 늙는다** | 게임서버는 NPC 서버의 틱을 **명령의 `IssuedAt`에서 딴다.** 하트비트에는 그 값이 없다(`IGameServerLink`에 런타임의 틱이 없고, 넣으려면 계약을 바꿔야 한다). NPC 서버가 명령을 한동안 안 내면 이 값이 멈춘 것처럼 보이는데, **그것도 정보다** |
| **클라이언트는 Windows 전용이다** | `net10.0-windows` + WinForms다. `Npc.Tests`는 이 프로젝트를 참조하지 않는다 — 참조하면 CI 전체가 Windows 전용이 된다. 클라이언트는 수동 확인 대상이고, 프로토콜과 게임서버만 자동 테스트한다 |

## 잘 안 될 때

| 증상 | 원인과 조치 |
|---|---|
| 게임서버가 `link down`이고 NPC가 안 움직인다 | 양쪽 `--npcs`·`--time-scale`이 다르면 핸드셰이크에서 거절된다. 두 콘솔의 `roster hash`를 견준다 |
| 클라이언트가 "게임서버를 찾는 중…"에서 안 넘어간다 | 게임서버의 `--client-port`와 클라이언트의 `--port`가 같은지 본다 (기본 7020) |
| 인스펙터가 "NPC 서버 미연결" | NPC 서버가 안 떴거나 `--port`가 다르다. `--npc-http`의 주소를 확인한다. **클라이언트는 이 상태로도 계속 돈다** |
| 킬스위치 버튼이 "미연결"만 뜬다 | NPC 서버에 `--dev-control`이 없다 |
| 지도 아래에 "마스터데이터 해시가 게임서버와 다르다" 경고 | 두 프로세스가 서로 다른 `masterdata/`를 읽고 있다. POI 이름과 위치가 어긋난 채 그럴듯한 화면이 나오는, 가장 찾기 어려운 종류의 사고다 |
| 창은 뜨는데 NPC가 하나도 안 보인다 | AOI가 플레이어 반경 1,200m다. `Home` 키로 월드 전체를 보고 NPC 무리 쪽으로 걸어간다 |

## 폴더

```
testbed/
  Npc.TestBed.Protocol/   클라이언트 프로토콜 (게임서버 ↔ 클라이언트). 프레임 코덱은 Npc.Wire 재사용
  Npc.TestGameServer/     게임서버 대역 — Npc.Sim 조립 + 10Hz 루프 + 링크/클라이언트 수신기
  Npc.TestClient/         WinForms 클라이언트 (net10.0-windows)
  scenarios/              데모 시나리오 3종 (기존 ../scenarios/ 와 별개다 — 틱 좌표가 다르다)
  run_demo.ps1            셋을 한 번에 띄운다 (UTF-8 BOM)
```

**단방향 잎이다.** 이 셋을 참조하는 프로젝트는 없다. `Npc.Tests`가 게임서버와 프로토콜은 참조하지만
클라이언트는 참조하지 않는다.
